# ADR-003: Монорепозиторий

- Статус: принято
- Дата: 2026-11-05
- Этап: 1 (каркас и дизайн-система)

## Контекст

Два приложения (mobile на React Native, api на NestJS) и три переиспользуемых пакета
(дизайн-система, типы, валидация). Команда небольшая, фичи будут наращиваться
быстро: брони, долги, доставки, геозоны. Нужно, чтобы общие типы и правила
валидации не расползались по репозиториям, а CI проверял всё сразу.

## Решение

- **pnpm workspaces** — быстрые установки, `workspace:*`-протокол для внутренних
  пакетов, один lockfile на весь репозиторий.
- **Turborepo** — оркестрация и кэширование задач `lint`, `typecheck`, `test`,
  `build`; `dev` поднимает api и mobile одной командой.
- **`node-linker=hoisted`** в `.npmrc` — официальная рекомендация Expo для
  монорепозиториев на pnpm: Metro не умеет разрешать pnpm-симлинки «из коробки».
- Структура:
  - `apps/mobile` — Expo-приложение (Expo Router, Zustand, Reanimated 3);
  - `apps/api` — NestJS: healthcheck + pino-логи + заглушка auth + Prisma;
  - `packages/ui` — дизайн-система: токены, темы, базовые компоненты;
  - `packages/types` — общие доменные типы (роли, healthcheck, конверты);
  - `packages/validation` — zod-схемы.
- **Source-пакеты**: внутренние пакеты отдают исходники (`main: src/index.ts`),
  Metro транспилирует TS сам — отдельная сборка dist на этом этапе не нужна.
  api (tsc/nest build) пока не импортирует внутренние пакеты: их dist-сборка и
  подключение к api запланированы на этап 2, вместе с первой бизнес-фичей.
- **Ветвление**: `main` — стабильная (прямые пуши закрыты процессом), задачи —
  в `feature/*`, слияние только через PR с зелёным CI. Коммиты — Conventional
  Commits, атомарные.
- **CI** — GitHub Actions: один job `verify` (lint → typecheck → test → build через
  `pnpm check`), кэш pnpm. Секретов не требует: используется встроенный GITHUB_TOKEN.
- **Dev-инфраструктура** — docker-compose (PostgreSQL+PostGIS, Redis), переменные —
  в корневом `.env` (шаблон `.env.example`, сам файл в `.gitignore`).

## Рассмотренные альтернативы

- **Nx** — мощный, но тяжеловат для трёх пакетов; Turborepo даёт то же с меньшей
  конфигурацией.
- **Два репозитория (mobile + api)** — рассинхрон общих типов, два CI, боль при
  сквозных изменениях.
- **Bun workspaces** — экосистема ещё не догнала pnpm по стабилизации для RN.

## Последствия

- ✓ Сквозные изменения (тип роли, токен цвета) — одним PR.
- ✓ `pnpm dev` поднимает всё сразу; CI один и зелёный.
- ✗ Hoisted-линкер лишает преимуществ строгой изоляции pnpm — следим за
  конфликтами версий через lockfile и `pnpm why`.
- ✗ До этапа 2 api дублирует пару типов (healthcheck) локально — осознанный
  компромисс ради простого build-пайплайна на каркасе.
