# ADR-003: Монорепозиторий

- Статус: **Принято**
- Дата: 2026-11-05
- Этап: «фундамент»

## Контекст

Три части продукта (mobile, api, общие пакеты) должны жить в одном месте:
тип `UserRole` меняется один раз и сразу виден и в приложении, и в API, и в zod-схеме.
CI должен проверять всё дерево одним прогоном.

## Решение

**pnpm workspaces + Turborepo.**

```
agromoll/
  apps/
    mobile/   (@agromoll/mobile)  — Expo, зависит от @agromoll/ui
    api/      (@agromoll/api)     — NestJS, зависит от @agromoll/types
  packages/
    ui/       (@agromoll/ui)      — дизайн-система: токены + компоненты
    types/    (@agromoll/types)   — общие типы, zero-dependencies
    validation(@agromoll/validation) — zod-схемы, зависит от @agromoll/types
```

### Ключевые решения

1. **`node-linker=hoisted` в `.npmrc`.** Expo/Metro исторически плохо дружат
   с pnpm-симлинками (резолв модулей и worklets). Плоская установка снимает целый
   класс проблем ценой менее строгой изоляции — для этапа «фундамент» это осознанный
   обмен.

2. **Задачи Turborepo** (`turbo.json`): `build`, `lint`, `typecheck`, `test`, `dev`
   (persistent), `db:generate`. Зависимости учитывают порядок: `typecheck`/`test`
   ждут `^build` (api типизируется по собранным `dist` пакетов) и `db:generate`
   (api требует сгенерированный Prisma Client).

3. **Двойная точка входа `packages/ui`**: `"react-native": "src/index.ts"` (Metro
   собирает TS-исходники напрямую — source maps и platform-файлы) и
   `"main": "dist/index.js"` (совместимость с любым будущим не-metro потребителем).
   Mobile-приложение типизируется по исходникам через `paths` в tsconfig.

4. **Разделение пакетов по ответственности**: `types` — без зависимостей (его импортируют
   все), `validation` — zod поверх типов (единственный источник схем), `ui` — только
   React Native-слой.

5. **CI одним workflow** (`.github/workflows/ci.yml`): lint → build → typecheck → test
   для всех пакетов, плюс отдельная job, которая поднимает `docker compose`
   (PostgreSQL + PostGIS + Redis), применяет миграции и проверяет `postgis_version()`.

## Рассмотренные альтернативы

- **Nx** — мощнее (генераторы, кэш-инференс), но больше магии и конфигурации;
  для 5 пакетов Turborepo даёт то же кэширование без изучения Nx-специфики.
- **Lerna** — фактически заброшен; его роль (версионирование) на приватном
  монорепо не нужна.
- **Отдельные репозитории** — versions hell с первого дня: типы придётся
  публиковать/синхронизировать руками, CI размножится.

## Последствия

- ✅ Атомарные PR через стек: изменение типа протаскивается во все пакеты одним коммитом.
- ✅ `pnpm dev` поднимает api и mobile одной командой; turbo кэширует сборки.
- ⚠️ Hoisted-режим: возможны конфликты дублирующихся несовместимых версий
  (пока не встретились; строгий pnpm-режим можно включить после отказа от Expo
  или перехода на его официальную pnpm-поддержку).
- ⚠️ Разработчику нужно помнить о порядке: `pnpm build` перед первым `pnpm dev`
  (turbo делает это сам через `dependsOn: ["^build"]`).
