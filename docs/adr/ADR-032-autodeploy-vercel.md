# ADR-032: Автодеплой Vercel

- Статус: **Принято**
- Дата: 2026-11-09
- Этап: v0.6.0 «Push, автодеплой, арбитраж, карта, админ» (подэтап B)
- Связанные: ADR-001 (стек), ADR-022 (URL API вшивается на сборке),
  DEPLOY.md (план публикации API)

## Контекст

Web-версия (Expo export) живёт на Vercel — проект `agromoll-web`,
https://agromoll-web.vercel.app. До v0.6.0 деплой был ручным:
разработчик запускал `vercel deploy` локально. Между мерджем в `main`
и обновлением сайта проходило время; «забыл задеплоить» — регулярный
источник рассинхрона кода и сайта.

## Решение

### GitHub Actions на push в main

Workflow `.github/workflows/vercel-deploy.yml`:

1. **Проверка секрета** `VERCEL_TOKEN` — если секрета нет, workflow
   падает СРАЗУ с понятным сообщением («добавьте в Settings → Secrets»),
   а не загадочным 401 от CLI на пятом шаге.
2. `pnpm install --frozen-lockfile` + `pnpm turbo run build` — тот же
   билд, что в CI: деплой не стартует, если приложение не собирается.
   Vercel пересоберёт remotely по `vercel.json` (buildCommand), локальная
   сборка — только гейт качества.
3. **Линк проекта** `.vercel/project.json` генерируется по ходу:
   orgId/projectId берутся из Vercel API **по одному токену** — отдельные
   секреты VERCEL_ORG_ID/VERCEL_PROJECT_ID не нужны (меньше ручных
   шагов настройки, меньше мест для опечатки).
4. `vercel deploy --prod --yes --token=…` из `apps/mobile`.
5. **Smoke-проверка**: `curl -I` главной, ожидание 200 с 6 попытками
   (CDN прогревается), при провале — подсказка про rollback.

Триггер — только `main` (деплоить feature-ветки в прод нельзя) +
`workflow_dispatch` для ручного повтора при сбое CDN-проверки.

### Почему GitHub Actions, а не Vercel Git Integration

У Vercel есть встроенный деплой по push — он отключён в пользу GitHub
Actions по трём причинам:

1. **Единая точка входа**: CI (тесты, e2e, миграции) и деплой — один
   список экшенов в одном месте; журнал деплоя рядом с журналом тестов.
2. **Гейт перед деплоем**: Vercel Git-интеграция деплоит по своему
   внутреннему решению; в Actions порядок шагов явный и контролируемый
   (build упал → деплоя нет).
3. **Один секрет**: Actions-подход требует только VERCEL_TOKEN;
   Git-интеграция требовала бы установки Vercel-приложения и привязки
   репозитория (больше ручных шагов владельцем).

### Ручной деплой одной командой

`pnpm deploy:vercel` (scripts/deploy-vercel.mjs): токен из локального
`.env` (никогда не коммитится), поиск проекта по API, сборка, деплой,
smoke-проверка. Для случаев «нужно задеплоить срочно, не через PR».

### Отсутствие секрета — ручной шаг владельца

Создать секрет в GitHub может только владелец репозитория. Workflow
сообщает об этом явно (`::error::` — видно в сводке PR). Это
единственный шаг настройки; после него деплои полностью автоматические.

### Откат

`npx vercel rollback agromoll-web --token=…` или Promote to Production
в консоли. Моментально: CDN переключается на предыдущую сборку без
пересборки. Плохой деплой — не катастрофа: откат занимает секунды.

## Последствия

- Мердж в `main` = обновление сайта (минуты, без участия человека).
- Добавлен `deploy:vercel` в корневой package.json.
- Секрет VERCEL_TOKEN добавляется владельцем вручную (один раз);
  VERCEL_ORG_ID/VERCEL_PROJECT_ID не нужны — резолвятся по токену.
- `apps/mobile/.vercel/` в .gitignore (линк генерируется на лету).
- Публичный API ещё не опубликован (см. DEPLOY.md): сайт честно
  показывает «Сервер не настроен», пока EXPO_PUBLIC_API_URL не задан
  в настройках проекта Vercel — автодеплой этого не меняет.
