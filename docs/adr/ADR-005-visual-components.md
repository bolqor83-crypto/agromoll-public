# ADR-005: Визуальные компоненты v0.2.0

- Статус: **Принято**
- Дата: 2026-11-05
- Этап: v0.2.0 «Бронирование»

## Контекст

В v0.1.0 были токены и 6 базовых компонентов. В v0.2.0 появились реальные
данные (лента, брони) — а с ними три состояния, которых не было: «загружается»,
«пусто» и «переключение раздела». Философия неизменна (ADR-002): 4 утра,
улица, перчатки, спешка — интерфейс обязан быть быстрым, крупным и спокойным.

## Решение

### 1. Skeleton вместо спиннера

**Мерцающий плейсхолдер (Reanimated, пульс opacity ~1 c), форма повторяет
карточку товара (`SkeletonCard`: квадрат-«фото» + строки).**

Почему не `ActivityIndicator`:

- спиннер с вращением считывается как «что-то крутится, ждите» и создаёт
  ощущение спешки — против философии «спокойного утра»;
- skeleton показывает **куда** придёт контент, экран не «прыгает» при
  появлении данных;
- пульс 0.45 → 0.9 прозрачности в такте ~1 c — медленнее и мягче, чем
  вращение; в тёмной теме скелет на токене `border` не светится.

### 2. EmptyState с геометрическими иллюстрациями

**Иллюстрации собраны из примитивов дизайн-системы (скруглённые
прямоугольники, круги, кольца) в токенах темы; 4 сюжета: корзина, ящик,
радар, календарь. Никаких стоковых картинок и Lottie.**

Почему:

- стоковые иллюстрации тянут чужую стилистику и вес; Lottie — ещё один
  формат ассетов и рантайм;
- геометрия из токенов автоматически корректна в тёмной теме
  (`primaryMuted` меняется вместе с темой) — иллюстрации «бесплатно»
  дву-тематные;
- EmptyState — это не ошибка: 1–2 строки текста + опциональное действие
  («Обновить», «Выставить лот»), без тревожных цветов.

### 3. Icon — обёртка над Ionicons (outline)

**Один набор (Ionicons), один стиль (outline), один размер по умолчанию
(24 px), цвета — семантические токены.** Обёртка нужна, чтобы размер и
палитру нельзя было «забыть» в новом экране; `tint` остаётся для
иллюстраций.

### 4. TabBar с pill-индикатором

**Презентационный компонент (`items`/`activeKey`/`onChange`), интеграция
с expo-router — через `tabBar`-проп `Tabs` (адаптер `RoleTabsBar` в
приложении).**

Почему презентационный, а не «компонент навигации»:

- packages/ui не должен зависеть от expo-router — иначе его нельзя
  использовать вне этого приложения и сложно тестировать;
- pill-индикатор переезжает между вкладками spring-ом (200–300 мс): глаз
  ловит движение, а не перечитывает подписи;
- каждая зона вкладки ≥ 48 px (перчатки), активная подпись зелёная и
  жирная, неактивные — приглушённые.

Вкладки по ролям: Покупатель «Лента»/«Мои брони», Продавец
«Витрина»/«Входящие», Доставщик «Радар»/«Мои доставки». Роль выбирается
на входе и меняется кнопкой «Сменить роль» на каждом экране — до
настоящей аутентификации это честнее, чем «вечный» выбор в табах v0.1.0.

### 5. Pull-to-refresh с вращающимся зелёным кругом

**На native — собственная механика на Reanimated: протяжка крутит круг
пропорционально смещению, отпускание после порога (72 px) запускает
обновление с лёгким haptic; при обновлении круг вращается непрерывно
(1 оборот / 0.8 c). На web — стандартный `RefreshControl` с цветом
`primary`: браузерный скролл не «протягивается» за начало списка.**

Круг — кольцо с одним зелёным сегментом (`borderTopColor: primary`):
вращение видно, при этом элемент спокойнее «бегущего» спиннера.

### 6. Микро-моменты

- **Haptics** на всех ключевых действиях: создание брони, подтверждение,
  отмена, принятие корректировки, переключение вкладки (`selectionAsync`),
  порог pull-to-refresh (`impactAsync` light). На web тихо игнорируется.
- **Spring-анимации** кнопок сохранены из v0.1.0; детальный экран лота
  входит spring-ом (`FadeInDown/FadeInUp`).
- **Отступление от ТЗ: shared-element-transition карточки → детальный
  экран заменён spring-переходом.** `react-navigation-shared-element`
  несовместим с expo-router v4 / React Navigation v7 без форков; свой
  вариант на Reanimated shared values — отдельный проект. Spring-вход
  сохраняет непрерывность ощущения при текущих рисках. Вернёмся к
  shared-element на следующем этапе.

### 7. Офлайн-фолбэк с честным бейджем

Если API недоступен (нет `pnpm dev`, плохая сеть), экраны не падают, а
показывают демо-данные с янтарным бейджем «Демо-данные · API недоступен».
Это одновременно: зерновая сеялка для будущего офлайн-режима (v0.3.0 —
outbox и синхронизация) и честность — пользователь всегда понимает,
что смотрит не живые данные.

## Рассмотренные альтернативы

- **Lottie-иллюстрации** — красиво, но новый рантайм и ассеты; геометрия
  из Views дешевле и всегда в теме.
- **Прозрачный Overlay + затемнение для skeleton** — мельтешение;
  пульс мягче.
- **Material-стиль FAB «коробкой»** — против мягких скруглений системы;
  FAB сделан круглым с мягкой тенью и haptic.
- **Nested tabs (роли сверху, разделы снизу)** — две панели вкладок
  одновременно: пользователь путается, какая за что отвечает. Выбран
  вход-по-роли.

## Последствия

- ✅ Все состояния данных (загрузка/пусто/ошибка/контент) отрисованы
  в обеих темах; скриншоты — docs/design/screenshots/.
- ✅ packages/ui остаётся переносимым (нет expo-router в зависимостях).
- ⚠️ Кастомный pull-to-refresh — свой код жеста; покрыт ручной проверкой
  в браузере, на устройствах проверяем в следующем спринте.
- ⚠️ Shared-element-переход — отложенный долг (см. п. 6).
