# ADR-009: Визуальные паттерны v0.3.1 — «проваливание» без потери простоты

- Статус: **Принято**
- Дата: 2026-11-06
- Этап: v0.3.1 «Безопасность + визуальная полировка»

## Контекст

v0.3.0 функциональна, но ощущается «набором экранов»: переходы —
системный fade, статусы меняются телепортом, загрузка — пульсирующие
прямоугольники, модалки — линейный системный slide. Философия
(ADR-002/005: простота, понятность, полезность, приятность) не
нарушена — но «приятность» не дотянута до тактильного уровня,
к которому привыкли пользователи нативных приложений.

Цель v0.3.1: интерфейс, в который «проваливаешься» — переходы объясняют
иерархию (откуда пришёл контент), микро-анимации подтверждают действия,
а тактильные отклики дают ощущение физического объекта. Без новой
бизнес-логики и без смены токенов.

## Решение

### 1. Переходы: почему НЕ react-native-screen-transitions

Исходная идея — библиотека `react-native-screen-transitions`
(`createBlankStackNavigator`, пресеты `SharedIGImage`/`SharedAppleMusic`).
Исследование на момент v0.3.1 показало несовместимость со стеком
проекта (Expo SDK 52 / React 18.3 / Reanimated 3.16 / expo-router 4.0):

- **v4.x** требует React ≥19.2, Reanimated ≥4, `react-native-worklets`,
  `react-native-teleport` — это Expo SDK 56 (стартер библиотеки живёт
  именно там); миграция SDK — отдельный этап, не «полировка»;
- **v3.13** требует `react-native-teleport` (наттивный модуль, вне
  Expo Go) и `@react-navigation/elements` ≥2; интеграция с expo-router
  построена на `unstable_integrateWithRouter`, которой в expo-router
  4.0.22 **нет** (появилась в SDK 53+);
- **v2.4.x** не имеет `createBlankStackNavigator` вовсе;
- во **всех** проверенных версиях (2.4.1–3.13.0) пресет `SlideFromBottom`
  содержит сломанный код (литеральная опечатка `eight` вместо `height`
  в interpolator) — признак сырой экосистемы.

Вывод: тянуть библиотеку ради двух эффектов — риск ломки SDK и
невозможность проверить нативное поведение. Все эффекты реализованы
вручную на Reanimated 3 (уже в стеке):

- **«Карточка раскрывается в экран»** (shared-element-морф): карточка
  ленты при нажатии замеряет фрейм «фото» (`measureInWindow` →
  singleton `src/lib/transition.ts`), детальный экран забирает фрейм
  одноразово и «вырастает» из него: transform вокруг центра
  (translate + scale по обеим осям) доводится spring-пружиной ~300 мс.
  Fallback: нет фрейма или платформа без measure → обычный fade-in
  (+страховочный таймер 250 мс, чтобы блок не остался невидимым).
- **Модалки-листы**: `SheetModal` — контент выезжает снизу
  spring-физикой (~300 мс), фон-затемнение проявляется, выход —
  250 мс с догоном размонтирования (системный Modal не умеет анимировать
  закрытие). Заменил `animationType="slide"` в обеих модалках.

При апгрейде до SDK 53+ библиотеку можно пересмотреть — эффекты уже
изолированы в компонентах.

### 2. Микро-анимации: словарь, не салат

Каждая анимация что-то значит (иначе она мусор):

| Эффект                      | Где                                    | Параметры                                             |
| --------------------------- | -------------------------------------- | ----------------------------------------------------- |
| staggered-вход карточек     | лента, брони — только первая отрисовка | translateY 12→0 + fade, 40 мс между карточками, кэп 8 |
| морф цвета бейджа статуса   | `Badge`                                | 300 мс, `interpolateColor`, текст — cross-fade        |
| пульс точки синхронизации   | `ConnectionBadge`                      | 1→0.6→1, цикл 2 с, только «Синхронизация…»            |
| появление пустого состояния | `EmptyState`                           | scale 0.9→1 spring + fade, 400 мс                     |
| press-отклик                | `Button`, `Card`                       | scale 0.97 + withSpring (с v0.2.0)                    |

Stagger только при первом появлении списка (state-флаг): рефреш и
возвраты на экран не «перескакивают» карточками заново.

### 3. Shimmer вместо пульсации

Пульсация opacity (v0.2.0) — «что-то происходит»; shimmer — «данные
загружаются сюда, слева направо»: блик шириной 45% с градиентными
краями (expo-linear-gradient) проходит блок за 1.5 с, loop без стыка
(старт и финиш за пределами блока). База — `surfaceElevated` темы,
блик — на 8% светлее (`lighten` в чистом модуле `color.ts` — тоже
для тестов). Skeleton используется только в ленте и списке броней.

### 4. Тактильная карта — три слова словаря

`packages/ui/haptics.ts`: `tap()` (impact Light — кнопки, карточки),
`success()` (notification Success — бронь, синхронизация), `warning()`
(notification Warning — конфликт, истечение TTL) + `selection()` для
вкладок (B6). Правила:

- **не более одного сигнала за 150 мс** — сетка быстрых нажатий не
  превращается в жужжание (unit-тест на fake timers);
- все вызовы приложения идут через карту — единая точка настройки
  и отключения;
- ошибки expo-haptics (web, неподдерживаемые устройства) гасятся:
  haptics — приправа, не блюдо.

Истечение TTL брони: экран «Мои брони» сравнивает предыдущие статусы
(реф-карта), и если живая бронь стала `expired` — один warning,
а не на каждый рендер.

### 5. Tab bar: физика переключения

Cross-fade иконок (два слоя с встречными прозрачностями, 200 мс) +
подпрыг scale 1→1.1→1 spring; подложка — `expo-blur` (intensity 40,
tint по теме, поверх 70% surface) — контент «просвечивает» при
скролле; на web blur недоступен — solid surface (как раньше).
Тактильный отклик — `selection()` из карты (из RoleTabsBar убран дубль).

### 6. Пустые состояния: строка «что сделать»

Каждое пустое состояние отвечает на вопрос «и что теперь?»: лента —
«Пока тихо. Обновите или загляните позже» + кнопка «Обновить»; брони —
«Здесь появятся ваши заказы. Начните с ленты» + кнопка «В ленту».
Иллюстрации — те же геометрические (без стоковых картинок), но
появляются (scale 0.9→1 + fade, 400 мс spring) — пустой экран живой,
а не простыня текста.

### 7. Токены и тёмная тема

- новый токен `scrim` (затемнение под модалками: светлая — тёплое
  rgba(15,20,17,.45), тёмная — rgba(0,0,0,.6)) вместо rgba-литералов
  в компонентах;
- тень FAB витрины — из `shadow[mode]`-токенов, не хардкод;
- shimmer/skeleton/пустые состояния работают от палитры темы:
  тесты проверяют, что база скелета в тёмной теме действительно тёмная
  и блик не превращается в белую вспышку; скриншоты обеих тем —
  в `docs/design/screenshots/v0.3.1/`.

## Тестирование

Без эмулятора в песочнице нативные эффекты проверяются тремя слоями:
unit (троттлинг haptics, lighten, консистентность тем — vitest),
web-экспорт собирается (typecheck/lint/build), скриншоты реального
приложения (лента, детальный экран, модалка, shimmer, пустые
состояния — светлая и тёмная). Переходы на устройствах проверяются
вручную по чек-листу DoD.

## Последствия

- «Приятность» перестала быть декларацией: переходы объясняют
  происхождение контента, подтверждения — тактильные.
- Reanimated-worklet'ы уже в приложении — нового нативного кода нет
  (expo-linear-gradient и expo-blur — пакеты Expo SDK 52, работают
  в Expo Go).
- Морф и stagger изолированы в компонентах: при апгрейде SDK и/или
  переходе на react-native-screen-transitions замена локальна.
- Тактильная карта — единая точка: отключить вибрацию globally или
  настроить по культурам рынка можно в одном файле.
