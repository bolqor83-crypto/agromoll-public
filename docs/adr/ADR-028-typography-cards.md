# ADR-028: Типографика и карточки

- Статус: **Принято**
- Дата: 2026-11-07
- Этап: v0.6.2 «Design & UX Excellence» (подэтап B)
- Связанные: ADR-002 (дизайн-система), ADR-009 (визуальные паттерны),
  ADR-024 (скругления листов), ADR-027 (анимации), AUDIT-v0.6.2.md

## Контекст

Аудит v0.6.2 (подэтап A) показал: дизайн-система фундаментально здорова,
но приложение выглядит «по-разному» на платформах (системный шрифт:
Roboto на Android, SF Pro на iOS), карточки слабо отделяются от фона
(одна плоская тень 0.07), 3 текстовых пары проваливают WCAG AA в светлой
теме и 1 — в тёмной, цифры сумм/часов «прыгают» при смене значений
(пропорциональные цифры), кнопки pill конфликтуют с карточками по
«радиус-языку», нет destructive-варианта.

## Решение

### 1. Шрифт — Inter (400 / 500 / 600 / 700)

**Почему Inter, а не Manrope.** Критерии: (а) близость к SF Pro —
пользователь просил «как айфон»; (б) кириллица из коробки; (в) табличные
цифры (OpenType tnum); (г) стабильность метрик на iOS/Android/web;
(д) поддержка expo-font из коробки (@expo-google-fonts/inter).

- **Inter**: метрики и x-height спроектированы под экраны и визуально
  ближайший «родственник» SF Pro; полный кириллический набор в каждом
  начертании; tnum есть; поддерживается Google Fonts (метаданные,
  обновления). Выбран.
- **Manrope**: геометрический, характерный, но шире и «дисплейнее» —
  на caption 13px читаемость хуже; в мелких размерах требует больших
  межстрочных; для рыночного UI с цифрами (цены, часы) Inter нейтральнее
  и стабильнее. Отклонён.

Четыре начертания покрывают все веса приложения: 400 (body/caption),
500 (промежуточный акцент), 600 (title/button/badge/таб-бар),
700 (display, цены). Загрузка — `useFonts` в корневом layout; пока
шрифты едут, показывается BootSplash без текста — исключён «скачок»
текста после подмены шрифта. Токены (`font` + `fontFamilyForWeight`)
живут в tokens.ts; компоненты до загрузки шрифта получают нативный
fallback (отсутствующий fontFamily в RN не роняет рендер).

### 2. Размеры и ритм

| Вариант | Было  | Стало                         | Почему                                                              |
| ------- | ----- | ----------------------------- | ------------------------------------------------------------------- |
| display | 34/41 | **32/40**, letterSpacing −0.4 | верхняя граница спеки (28–32), трекинг крупных заголовков как в iOS |
| title   | 22/28 | 22/28, letterSpacing −0.2     | чуть плотнее — выразительнее                                        |
| body    | 17/24 | 17/**26**                     | межстрочный 1.5 по спеке — «воздушно» на длинных строках            |
| caption | 13/18 | 13/18                         | без изменений                                                       |
| button  | 17/22 | 17/22, letterSpacing 0.1      | лёгкий набор текста в кнопках                                       |

Числа (цены, суммы, часы, рейтинг) — `fontVariant: ['tabular-nums']`
(проп `numeric` у Text; AnimatedNumber — включён по умолчанию): цифры
одинаковой ширины, счётчики «дышат», но не прыгают.

### 3. Контраст WCAG AA (главный фикс B)

Программный расчёт (аудит §3): textMuted светлой темы #8A9189 — 2.95:1
на фоне (FAIL). Новые значения:

- light `textMuted` → **#6B726A** (4.51:1 на background, 4.87:1 на surface);
- dark `textMuted` → **#868C82** (4.62:1 на surface, 5.13:1 на background);
- янтарный `warning` в светлой теме — только заливки/иконки/рамки,
  текст — `onWarning` (#7C4A0C, 7.27:1). Исправлены подписи в
  ConfirmDeliveryModal.

Пары зафиксированы юнит-тестом `contrast.test.ts` (пересчёт при каждом
изменении палитры — регрессия невозможна).

### 4. Карточки: глубина и состояния

- **Скругления**: единый «радиус-язык» — карточки **16** (radius.md,
  было 20), модалки-листы 20 (radius.lg, без изменений), бейджи pill.
- **Глубина в светлой теме**: тень заметнее (0.08/18px, offset 6) + на
  web двухслойная через `boxShadowWeb` («контакт с поверхностью» +
  мягкое рассеяние — настоящий многослойный box-shadow в CSS). На native
  RN-тени однослойные по своей природе; разница платформ не заметна
  глазу.
- **Тёмная тема**: тень на тёмном фоне физически не видна — глубину
  даёт усиленная рамка `borderStrong` (#3A423C) — «elevation через
  цвет» (подробнее — ADR-030). Токен `borderStrong` добавлен в обе
  палитры.
- **Состояния**: нажатие — spring scale 0.98 (было); фокус с клавиатуры —
  обводка 2px primary; disabled — opacity 0.5 и блокировка нажатия.
- **Контент**: «фото» в деталях лота — aspectRatio 4:3 (была фикс.
  высота 148px) + overflow hidden — подготовлено под реальные фото и
  градиент читаемости. Бейджи получили иконки (time/leaf/locate/star)
  и paddingVertical 4 — «пилюля: иконка + текст».

### 5. Кнопки

- Скругление **16** (было pill 999) — как у карточек.
- **primary**: зелёная заливка, min-height 56 (lg) / 48 (md), мягкая
  тень в светлой теме, spring 0.97 + haptic.
- **secondary** = outline: прозрачный фон, обводка 1.5px primary,
  зелёный текст (было — мятная заливка primaryMuted). Мятная подложка
  осталась у бейджей и таб-пилюли — кнопка теперь честно «вторичная».
- **danger** (новый): деструктивные действия — янтарная обводка +
  10% янтарная подложка + текст onWarning. Не заливка: сплошной янтарь
  с белым текстом даёт 2.1:1 (провал AA), а философия ADR-002 —
  «срочность без тревоги». Красный запрещён.
- **ghost**: без изменений (нейтральная рамка).

## Последствия

- Одинаковый современный вид на всех платформах; +4 файла шрифта
  (~1 МБ ассетов, грузятся до первого экрана, не блокируют логику).
- Обновлены tokens.test.ts (типографика/тени/шрифт), новый
  contrast.test.ts, рендер-тест дизайн-системы (sizes/fonts/radius).
- secondary-кнопки меняют вид во всём приложении сразу (осознанно:
  единообразие важнее точечного вида).
- Осталось на ADR-030: формальная проверка всех пар тёмной темы,
  borderStrong-политика, max-width на больших экранах.
