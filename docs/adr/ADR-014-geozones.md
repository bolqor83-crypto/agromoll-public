# ADR-014: Геозоны — PostGIS geography, GIST и платформенно-разделённая карта

- Статус: **Принято**
- Дата: 2026-11-08
- Этап: v0.5.0 «Публичный рейтинг · Геозоны · Доставка попутчиками» (подэтап B)

## Контекст

Рынок — физическое место: покупатели приходят на линии продавцов,
доставщики ездят между точками. До v0.5.0 географии не было вовсе:
листинг имел только номер линии (`lineNumber`), покупатель — ничего.
Спецификация v0.5.0-B требует: точки покупателей, линии продавцов,
коридоры доставщиков, поиск «рядом» и карту.

## Решение

### Одна модель на три вида геозон

`GeoPoint` (kind: `buyer_point` / `seller_line` / `delivery_corridor`)
— единая таблица `geo_points`. Коридор — та же точка с маршрутом
(`corridorFrom`/`corridorTo` — jsonb {lat, lng}) и транспортными
атрибутами (`vehicleType`, `maxWeightKg`, `isRefrigerated`);
базовые координаты строки = точка старта маршрута.

Почему одна модель, а не три таблицы: все три вида участвуют в одних
и тех же запросах («кто рядом»), имеют одного владельца и одинаковый
жизненный цикл (создать → обновить → деактивировать). Разделение
таблиц утроило бы код ради ложной «чистоты».

Роль определяет вид: buyer создаёт `buyer_point`, seller —
`seller_line`, driver — коридоры (403 при несоответствии). Геозона
деактивируется (`isActive=false`), но не удаляется — история
местонахождений нужна спорам и репутации.

### PostGIS geography(Point, 4326), а не geometry

Координаты хранятся дважды:
- `latitude`/`longitude` (Float) — клиентский контракт, доступен
  через Prisma-клиент без сырых SQL;
- `geog` (`Unsupported("geography(Point,4326)")`) — PostGIS-колонка,
  заполняемая **триггером БД** при INSERT/UPDATE: приложение не может
  рассинхронизировать пару, даже пишая напрямую в SQL.

Почему geography, а не geometry: `geography` считает расстояния по
сфероиду Земли — `ST_DWithin(geog, geog, meters)` принимает метры
напрямую, без знания проекции. Рынок живёт в метрах («в 2 км от
меня»), а не в градусах. Плата — небольшая вычислительная
дороговизна против geometry; для рынка одного города она несущественна.

GIST-индекс на `geog` обслуживает `ST_DWithin`/`ST_Distance`.
Prisma не описывает GIST-индексы и триггеры — они живут в миграции
`20261108100000_geo_points`; CI-проверка «миграции = схема»
исключает имя индекса из diff (как и системные таблицы PostGIS).
E2E-производительность: 1000 точек, nearby < 100 мс — GIST даёт
это с запасом (замер прямым вызовом сервиса, без HTTP-оверхеда).

### API

- `POST /geo/points` — точка/линия (роль обязана соответствовать
  виду); `POST /geo/corridors` — маршрут (только driver).
- `GET /geo/points/nearby?lat&lng&radiusMeters&kind` — активные
  точки в радиусе (`ST_DWithin`), с честными `distanceMeters`
  (`ST_Distance`), сортировка по близости.
- `GET /geo/corridors/nearby?lat&lng&radiusMeters` — маршруты, чья
  ЛИНИЯ `ST_MakeLine(from, to)` проходит не дальше радиуса от точки:
  «кто едет мимо меня», а не «кто стоит рядом».
- `PATCH /geo/points/:id`, `DELETE /geo/points/:id` (деактивация) —
  только владелец (403), 404 для чужих идентификаторов.
- Валидация (zod): lat ∈ [-90, 90], lng ∈ [-180, 180],
  radiusMeters ∈ [10, 5000].

Радиус по умолчанию — ENV `DEFAULT_GEO_RADIUS_METERS=2000`: 2 км
покрывает весь рынок и ближайшие подходы, не заставляя город.

### Карта: платформенно-разделённая (native / web)

- **Native (iOS/Android): `react-native-maps`** — входит в Expo Go
  (предbuild не нужен), даёт настоящие тайлы, маркеры и перетаскивание
  пина. Выбор для прода — стандарт индустрии.
- **Web: схематичная SVG-карта без тайлов.** Почему не
  react-native-web-maps/Leaflet: тайловые библиотеки тянут
  DOM-зависимости и требуют провайдера тайлов (ключ/лицензия) ради
  MVP-задачи «показать точки рядом»; главное — они ломают
  `expo export --platform web` (подэтап D — деплой на Vercel).

Механика разделения — расширения Metro: `MapView.native.tsx`
(импортирует react-native-maps) и `MapView.web.tsx` (SVG), общий
контракт `MapCanvasProps`. Импорт `react-native-maps` живёт ТОЛЬКО в
.native-файле, поэтому web-сборка не тянет библиотеку вовсе —
проверено: в dist её нет, `/map` экспортируется. TypeScript
разрешает суффиксы через `moduleSuffixes: [".web", ".native", ""]`.

Цвета (спецификация B): точки покупателей — синий `#3B6FA0`,
линии продавцов — фирменный зелёный `#2E6B4E`, коридоры — мягкий
янтарный `#C98A2D`.

### Мобильные экраны

- **«Карта рынка»** (вход с экрана ролей): геозоны вокруг позиции
  (экспо-location, отказ не блокирует — центр рынка), легенда,
  «кто едет рядом»; водитель публикует маршрут двумя тапами по
  карте + параметры транспорта.
- **«Моя точка»** (лента покупателя, витрина продавца): геолокация →
  перетаскиваемый пин → адрес/название → сохранение.
- **Фильтр «Рядом со мной»** на ленте: `/geo/points/nearby?kind=
  seller_line` → множество id продавцов → лента показывает только
  их лоты. Позиция: геолокация → моя сохранённая точка → центр
  рынка.

## Последствия

- Коридоры — фундамент подэтапа C: «радар» доставщика ищет заказы
  вдоль маршрута через `/geo/corridors/nearby`.
- Веб-карта схематична: показывает точки и позволяет выбирать
  координаты, но без тайлов и зума. Полноценная веб-карта — после
  MVP, если web-канал окажется востребован.
- `GeoPoint.radiusMeters` (по умолчанию 50) — персональный радиус
  видимости точки; в v0.5.0-B nearby-поиск использует радиус
  ЗАПРАШИВАЮЩЕГО, персональные радиусы пригодятся в C.
