# ADR-042: OTA-обновления через expo-updates

- Статус: **Принято** (публикация — после передачи EXPO_TOKEN)
- Дата: 2026-11-07
- Этап: v0.8.0 «Public Launch» (подэтап E)
- Связанные: ADR-041 (EAS Build, канал дистрибуции), ADR-022 (адрес API
  вшивается в бандл), ADR-032 (паттерн workflow с проверкой секрета)

## Контекст

Нативная сборка (ADR-041) — событие редкое: прогрев, очереди EAS,
переустановка на устройствах. При этом 95% правок до v1.0 — экраны,
логика, стили: чистый JS/TS, который Metro умеет доставлять поверх
установленного приложения (over-the-air). Ждать переустановки .apk из-за
исправленной кнопки — неприемлемо для демо-темпа.

## Решение

### expo-updates + EAS Update, канал `production`

- Пакет `expo-updates` установлен (`npx expo install`, версия выровнена
  с SDK 52 автоматом).
- `app.json`: `updates.url = https://u.expo.dev/<projectId>` (projectId
  появится после `eas init`, v0.8.0-D runbook) и
  `runtimeVersion.policy = "appVersion"` — версия канала = версия из
  app.json. Мёрж в main с новой версией = новый канал; старые сборки
  продолжают жить на своих версиях, рассинхрона нативного API не бывает.
- Workflow `.github/workflows/eas-update.yml`: push в main → сборка
  workspace-пакетов → `eas update --branch production --message auto
  <sha>`. Паттерн ADR-032: проверка секрета EXPO_TOKEN первым шагом с
  понятным сообщением; concurrency-группой гасим параллельные запуски;
  гейт на плейсхолдер projectId в app.json (пока `eas init` не выполнен,
  публикация падает с объяснением, а не уходит «в никуда»).

### Доставка

При запуске (и периодически в фоне) expo-updates спрашивает
`updates.url`; если на канале есть более новая публикация с тем же
runtimeVersion — скачивает и применяет при следующем запуске
(безопасный двухфазный апдейт: пользователь не видит «полуприложение»).

### Ограничения OTA (почему не отменяет EAS Build)

- **Нативный код не обновляется**: новые expo-модули, permissions,
  изменения `ios`/`android` секций app.json (bundleId, иконки, версия),
  нативные SDK → обязательная пересборка через EAS Build (ADR-041).
- **runtimeVersion обязан совпадать**: публикация видна только сборкам
  с той же версией app.json (policy appVersion). Обновили версию →
  нужен новый build, OTA-канал новый.
- Apple-политика: JS+ассеты поверх бинаря, собранного тем же
  Expo SDK, — допустимо; менять нативное поведение OTA нельзя
  (для нас и не нужно — iOS пока не собирается).

### Откат

```bash
npx eas update:rollback --branch production   # предыдущая публикация
npx eas update:rollback --branch production --backup-id <id>  # на конкретную
```
Откат тоже публикация: клиенты видят её при следующем обновлении.
Крайний случай (плохой бандл «залип» на устройствах) — пересборка
с bumped версией app.json: новый runtimeVersion-канал чист.

## Последствия

- Каждый мёрж в main автоматически доезжает до установленных приложений
  без участия пользователя — дисциплина CI становится ещё критичнее
  (юзер-тесты флоу в подэтапе F перед мержем, не после).
- Ручной шаг для владельца репозитория: EXPO_TOKEN в GitHub Secrets
  (Settings → Secrets → Actions); без него workflow честно падает.
- Web-версию OTA не касается: Vercel-деплой (ADR-032) обновляет её
  независимо и мгновенно.
