# ADR-001: Технологический стек

- Статус: принято
- Дата: 2026-11-05
- Этап: 1 (каркас и дизайн-система)

## Контекст

Рынок «АгроМолл» (Ростов-на-Дону) работает с 4:00 до 14:00. Три роли: покупатель
(владелец ларька), продавец (оптовик), доставщик (попутчик). Приложение используют
ранним утром, в спешке, часто на улице и в перчатках, на недорогих Android-устройствах
и iPhone. Нужен быстрый MVP с последующим быстрым наращиванием фич (брони, долги,
учёт часов, доставки с геозонами), одна небольшая команда, TypeScript везде.

## Решение

| Слой | Выбор | Почему |
| --- | --- | --- |
| Mobile | React Native + Expo (SDK 53, managed) | Одна кодовая база iOS/Android, OTA-обновления через EAS позже, минимум нативной возни. Expo Router — файловая маршрутизация и deep links из коробки |
| Навигация | Expo Router 5 | Файловые роуты, типобезопасность, web-поддержка для быстрых превью |
| Состояние | Zustand 5 | Минимум бойлерплейта, без провайдеров, достаточно для локального UI-состояния |
| Анимации | Reanimated 3 | Spring-переходы 200–300 мс на UI-потоке — «тактильность» без лагов |
| Backend | NestJS 11 | Модульность, DI, декораторы, единый стиль с Prisma; структура модулей масштабируется под домены (orders, debts, deliveries) |
| ORM | Prisma 6 | Типобезопасные запросы, декларативная схема, миграции |
| БД | PostgreSQL 16 + PostGIS | Реляционная целостность (заказы/долги/смены) + геоданные: геозоны рынка и трекинг доставщиков. Расширение закладывается в первой миграции |
| Кэш/очереди | Redis 7 | Заложен в docker-compose с первого дня: кэш прайсов, очереди броней, pub/sub — со следующих этапов |
| Валидация | Zod | Одна схема = и валидация, и TS-тип; переиспользуется между api и mobile |
| Сборка | pnpm workspaces + Turborepo | Быстрые установки, workspace-протоколы, кэширование и оркестрация задач lint/typecheck/test/build |

## Рассмотренные альтернативы

- **React Native CLI (bare)** — гибкость нативного кода не нужна на старте, зато дороже
  поддержка окружений. Managed Expo + config plugins покрывают foreseeable нужды.
- **Flutter** — отличный UI, но другая экосистема: нет переиспользования TS-типов с api.
- **Express/Fastify** — быстрее старт, но хуже структурность при росте числа модулей.
- **MongoDB** — есть 2dsphere, но реляционные связи (заявки↔прайсы↔оплаты↔смены)
  и транзакции для долгов/броней критичнее; PostGIS функционально сильнее для гео.

## Последствия

- ✓ Единый язык (TypeScript) и общие пакеты типов/валидации между mobile и api.
- ✓ Быстрый CI: фиксированные версии через lockfile, кэш Turborepo.
- ✗ Expo-ограничения при глубокой нативной кастомизации (принимаем на этом этапе).
- ✗ PostGIS требует расширения в миграциях и образа postgis/postgis в docker-compose.
