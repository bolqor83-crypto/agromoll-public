# ADR-001: Технологический стек

- Статус: **Принято**
- Дата: 2026-11-05
- Этап: «фундамент»

## Контекст

Рынок «Агро Молл» (Ростов-на-Дону) работает с 4:00 до 14:00. Три роли: покупатель
(владелец ларька), продавец (оптовик), доставчик (попутчик). Приложение используется
ранним утром, в спешке, часто на улице и в перчатках, на нестабильном мобильном интернете.
В перспективе: геозоны рынка, доставка, долги, учёт часов — то есть мобильный клиент
с картой и фоновыми процессами, и API с гео-запросами.

## Решение

| Слой        | Выбор                                     | Почему                                                                                                                                                                            |
| ----------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mobile      | **React Native + Expo (SDK 52, managed)** | Одна кодовая база iOS/Android + web для проверки; OTA-обновления через expo-updates; доступ к нативным модулям (геолокация, уведомления) без eject                                |
| Навигация   | **Expo Router 4**                         | Файловая маршрутизация, deep links, вложенные layout'ы (таб-бар трёх ролей), static rendering для web                                                                             |
| Состояние   | **Zustand**                               | Минимальный бойлерплейт, без провайдеров, TS-first. Redux/Redux Toolkit избыточны для домена «3 экрана → позже 10»                                                                |
| Анимации    | **Reanimated 3**                          | 60 fps на UI-потоке, spring-физика для тактильного отклика кнопок (см. ADR-002)                                                                                                   |
| API         | **NestJS 11**                             | Модульность и DI под три будущих домена (брони, долги, доставка), зрелый TS, готовые интеграции (pino, config, тесты)                                                             |
| ORM         | **Prisma 6**                              | Типобезопасные запросы и миграции из коробки; schema — единственный источник правды о БД                                                                                          |
| БД          | **PostgreSQL 16 + PostGIS 3.4**           | PostGIS закладывается в **первой** миграции: геозоны рынка и поиск попутчиков по радиусу появятся без миграционной боли. Расширение ставится в CI и локально идемпотентно         |
| Кэш/очереди | **Redis 7 (в docker-compose)**            | На этом этапе не подключается к коду — контейнер и переменная окружения заложены, чтобы следующий этап (rate-limit, pub/sub заказов, сессии) не требовал изменения инфраструктуры |
| Логи API    | **pino + nestjs-pino**                    | Структурированный JSON в проде, pino-pretty в разработке; healthcheck исключён из автологирования, чтобы не шуметь                                                                |

## Рассмотренные альтернативы

- **Flutter** — отличный UI, но нет переиспользования TS-типов между мобильным приложением
  и API; для команды с NestJS-бэкендом это удваивает стек.
- **PWA (React)** — дешевле, но слабые фоновые режимы, геолокация и push на Android/iOS
  в 4 утра критичны.
- **Express/Fastify** — быстрее и проще, но на горизонте трёх доменов потеряем
  структуру; NestJS даёт её с первого дня.
- **TypeORM** — менее строгая типизация, миграции слабее, чем у Prisma.
- **MongoDB** — гео-запросы есть, но реляционная природа домена (заказы, долги, смены)
  и транзакции важнее.

## Последствия

- ✅ Единый язык TypeScript от экрана до БД: `UserRole` один в `packages/types`,
  в zod-схеме и в Prisma-enum.
- ✅ OTA-обновления (expo-updates) позволят чинить утренние баги без ревью сторов.
- ⚠️ Expo-зависимость: часть нативных библиотек требует config-plugins (учтено,
  managed workflow пока покрывает потребности).
- ⚠️ Prisma Client генерируется в `node_modules` — задача `db:generate` встроена
  в turbo-цепочку typecheck/test/build.
