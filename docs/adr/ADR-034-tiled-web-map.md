# ADR-034: Плиточная карта web (Leaflet + OpenStreetMap)

- Статус: **Принято**
- Дата: 2026-11-10
- Этап: v0.6.0 «Push, автодеплой, арбитраж, карта, админ» (подэтап D)
- Связанные: ADR-014 (геозоны и первая карта), ADR-023 (code splitting),
  ADR-030 (тёмная тема и mapPalette), ADR-033 (арбитраж — не влияет,
  контекст этапа)

## Контекст

Web-карта рынка (v0.5.0, ADR-014) — схематичный SVG: относительная
проекция точек в окне ±2.2 км без зума и панорамирования. Для рынка
этого хватало «показать, кто рядом», но покупатель не видит реальную
географию: ряды рынка, выходы, улицы. Плиточная карта с реальными
тайлами закрывает это без нового контракта.

Native-карта (react-native-maps) уже плиточная — этот ADR касается
только web-платформы (`.web.tsx`), контракт `MapCanvasProps` не меняется.

## Решение

### Leaflet + OSM, vanilla — без React-обёрток

- **leaflet@1.9.4** (версия запинена) + **leaflet.markercluster@1.5.3**.
  Vanilla-использование в `useEffect`: react-leaflet добавляет
  React-обёртку поверх императивной DOM-библиотеки без выгоды для
  одного компонента, а react-native-web-maps тянет react-native-maps
  в web-сборку (чего ADR-014 как раз избегал).
- **Тайлы OpenStreetMap** (`tile.openstreetmap.org`, стандартный стиль):
  без ключей и регистрации. Fair use OSF: обязательная атрибуция
  (`attributionControl`), разумные границы zoom (12–19), без bulk-выгрузок.
  MVP-нагрузка рынка (десятки пользователей) — допустимое использование;
  при росте — свой стиль тайлов или провайдер (документированный долг).

### Динамический импорт и CSS-инъекция

- Leaflet грузится `await import('leaflet')` **внутри useEffect**:
  (1) тяжёлая зависимость (149 КБ) живёт в отдельном чанке и грузится
  только при показе карты (ADR-023); (2) static export пререндерит
  маршруты в Node — Leaflet трогает `window` на импорте и упал бы
  при статической генерации.
- CSS — **минимальная инъекция `<style>` из кода** (leaflet-helpers):
  полный `leaflet.css` тянет url()-ассеты дефолтных маркеров (мы их
  не используем — свои divIcon) и требует Metro-CSS-пайплайн
  (`experiments.css`). Инъекция идемпотентна, работает в jest без
  моков CSS, версия запинена — раскладка паноров Leaflet стабильна.

### Маркеры, кластеры, темы

- Маркеры — `L.divIcon` c круглыми HTML-пинами: заливка цветом вида
  геозоны (`markerColorFor` из mapPalette, ADR-030: покупатель — синий,
  продавец — зелёный, коридор — янтарный), обводка `pinHole` темы,
  подпись в `title` (экранирование пользовательского ввода).
- **Кластеризация** точек рынка (`MarkerClusterGroup`, радиус 40 px,
  spiderfy на максимальном зуме): пузырь со счётчиком на цвете
  продавца — плотные ряды рынка не сливаются в кашу.
- **Тёмная тема**: стандартные тайлы OSM светлые — фильтр
  `invert(1) hue-rotate(180deg)` на tile-pane (класс-модификатор
  контейнера, CSS из хелперов). Без второго провайдера тайлов;
  канва, атрибуция и зум-контролы перекрашены под тёмную палитру.
- Пин «моя точка» — перетаскиваемый маркер (`dragend` → `onPinChange`),
  тап по полю двигает пин или выбирает координату (`onTap`) — семантика
  SVG-версии сохранена, MyPointSheet изменений не потребовал.

## Альтернативы

- **Оставить SVG-схему** — отвергнуто этапом: реальная география рынка
  — половина ценности карты для покупателя.
- **react-leaflet** — отвергнуто: лишний слой абстракции ради одного
  компонента + требования к версии React.
- **Mapbox/2GIS/Yandex** — отвергнуто: ключи/токены и лимиты ради MVP;
  OSM без ключей закрывает задачу (fair use документирован).
- **Тёмные тайлы CartoDB** — отвергнуто: второй внешний провайдер ради
  темы; CSS-фильтр инверсии даёт сопоставимый результат без новых
  зависимостей.

## Последствия

- Web-бандл: +183 КБ в ОТДЕЛЬНОМ чанке (leaflet + markercluster),
  entry не разросся; загрузка — только при открытии карты/точки.
- Юнит-тесты — чистые хелперы (HTML маркеров, CSS, экранирование)
  без DOM; рендер-тесты карты не нужны — контракт тот же, экраны
  карты тестируются моками MapCanvas.
- Zoom-лимиты 12–19 и атрибуция — часть контракта fair use OSM;
  выносить в ENV не нужно (константы ADR-034).
- Нативная платформа не затронута: react-native-maps в Expo Go,
  платформенные файлы не видят чужих зависимостей (moduleSuffixes).
