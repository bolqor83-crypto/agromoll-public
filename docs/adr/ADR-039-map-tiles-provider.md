# ADR-039: Платные тайлы карты — провайдер по ключу, fallback OSM

- Статус: принято (v0.7.0-E)
- Дата: 2026-11-07
- Связанные: ADR-034 (тайловая карта — OSM-дефолт и fair use),
  ADR-022 (паттерн EXPO_PUBLIC_*-конфигурации на сборке)

## Контекст

ADR-034 выбрал открытые тайлы OpenStreetMap: без ключей, без биллинга,
для MVP-нагрузки рынка честно и достаточно. Тогда же зафиксирован долг:
«при росте — свой стиль/провайдер». v0.7.0 — этап «Scale»: web-версия
публична (Vercel), трафик карты растёт вместе с пользователями.
Политика тайлов OSM прямо просит heavy-пользователей уходить на
платного провайдера или свой стиль; остаться на стандартном
tile.openstreetmap.org при росте — риск деградации для всех и
неуважение к проекту OSM.

Подключение провайдера не должно требовать правки кода: выбор
(MapTiler / Mapbox / Thunderforest / Geoapify / свой тайл-сервер) —
решение деплоя, а не разработки.

## Решение

**Тайлы — конфигурация сборки, деградация — всегда OSM.**

### Конфиг (env сборки, паттерн ADR-022)

- `EXPO_PUBLIC_MAP_TILES_URL` — шаблон с обязательными `{z}/{x}/{y}`,
  ключ провайдера вшит в URL (Expo инлайнит EXPO_PUBLIC_* в бандл
  на сборке; на Vercel переменная задаётся в Project Settings,
  редеплой подхватывает).
- `EXPO_PUBLIC_MAP_TILES_ATTRIBUTION` — требование лицензии
  провайдера (HTML разрешён). **Не задана → авто-«© <host>»**:
  забыть атрибуцию конфиг не позволяет — она обязательна для любого
  провайдера тайлов.
- `EXPO_PUBLIC_MAP_TILES_MAX_ZOOM` — максимум зума (12..22), дефолт 19
  (контракт ADR-034).

Пусто или мусор (нет плейсхолдеров, не URL) → OSM-дефолт: ошибка
конфига не должна ломать экран карты («деградация, а не падение» —
тот же принцип, что S3-fallback в ADR-036/038).

### Runtime-фолбэк

Платный провайдер может лежать уже ПОСЛЕ сборки: ключ протух, квота
кончилась, домен недоступен. Слой тайлов слушает события Leaflet:
серия из 6 `tileerror` подряд без единой `tileload` (порог с запасом
на одиночные 404 живого провайдера) — слой снимается, ставится OSM
с его атрибуцией, в консоль пишется warn. Карта важнее провайдера:
пользователь видит рынок, а не серые плитки.

### Платформы

- **Web** (Leaflet) — полноценно: конфиг + runtime-фолбэк.
- **Native** (react-native-maps) — системные тайлы Apple/Google уже
  лицензированы платформой, ключи не нужны; подключение urlTemplate
  работало бы только на части Android-сборок. Осознанно не трогаем:
  платные тайлы — проблема публичной web-версии с её неограниченным
  трафиком; нативные сборки ограничены числом установок.

### Реализация

- `apps/mobile/src/map/tiles.ts` — чистая функция `resolveTileConfig`
  (все сценарии покрыты юнит-тестами) + модульный `TILE_CONFIG`,
  вычисленный при импорте (значение вшито в бандл на сборке).
- `MapView.web.tsx` — `addTileLayerWithFallback`: слой из конфига +
  слушатели tileload/tileerror.
- `turbo.json` — переменные добавлены в `env` задачи build (кэш
  инвалидируется при смене провайдера).

## Альтернативы

- **Остаться на OSM навсегда** — отвергнуто: этап Scale, публичный
  трафик; риск и неуважение к OSM (ADR-034 сам обещал переход).
- **Свой тайл-сервер с OSM-данными (self-hosted)** — отложено: он
  и есть «свой стиль» из ADR-034, но это отдельная инфраструктура
  (рендер, хранение, обновление) — не для этого этапа. Конфиг
  EXPO_PUBLIC_MAP_TILES_URL его подключит без правки кода, когда
  появится.
- **Провайдер в коде (константа)** — отвергнуто: выбор провайдера —
  решение деплоя; смена = правка кода + PR ради ключа.
- **Ключ провайдера отдельной переменной** — отвергнуто: у всех
  провайдеров разные схемы (query-ключ, path-ключ, JWT) — шаблон URL
  целиком в env покрывает всё без парсинга на клиенте.

## Тестирование

- Unit (mobile): resolveTileConfig — OSM-дефолт (пусто/пробелы/мусор
  без плейсхолдеров), валидный шаблон с атрибуцией и зумом,
  авто-атрибуция «© <host>» без www, clamp зума 12..22, мусор зума →
  дефолт, значения зума/атрибуции не влияют на OSM-ветку.
- E2E-проверка руками (DEPLOY.md): задать переменную → пересобрать →
  тайлы провайдера и атрибуция; убрать ключ из URL (невалидный) →
  сборка на OSM; «положить» ключ → серия ошибок → OSM в рантайме.

## Последствия

- Смена провайдера — переменная сборки + редеплой, код не трогаем.
- Рантайм-фолбэк меняет атрибуцию на OSM — легально и честно.
- Native-версии остаются на системных тайлах (задокументировано).
- Порог 6 ошибок — константа: подбирается по факту, если провайдер
  флейкит чаще (поднять нельзя через env — редко нуждается в смене).
