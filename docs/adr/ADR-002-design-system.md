# ADR-002: Дизайн-система

- Статус: **Принято**
- Дата: 2026-11-05
- Этап: «фундамент»

## Контекст

Приложением пользуются в 4:00–14:00, в спешке, часто на улице и в темноте, в перчатках.
Ошибка в заказе стоит денег; тревожный UI усиливает утренний стресс и приводит к ошибкам.
Философия: **простота** (одно очевидное действие на экране), **понятность** (язык рынка,
не софта), **полезность** (экономит время и деньги в моменте), **приятность**
(снижает стресс, а не усиливает).

## Решение

### Токены — единый источник правды (`packages/ui/src/tokens.ts`)

- **colors** (на каждую тему): `background`, `surface`, `surfaceElevated`, `primary`,
  `primaryMuted`, `accent`, `warning`, `text`, `textSecondary`, `textMuted`, `border`
  - служебные `onPrimary` / `onWarning` (цвет текста на заливке; в тёмной теме
    `primary` светлее, и текст на нём обязан быть тёмным).
- **typography**: `display 34/41`, `title 22/28`, `body 17/24`, `caption 13/18`,
  `button 17/22` — крупная, с высоким контрастом; на карточках минимум текста
  (фото → название → цена → бейдж).
- **spacing**: 4 / 8 / 12 / 16 / 24 / 32.
- **radius**: 12 / 16 / 20 + `pill` — единообразные iOS-like скругления.
- **motion**: 200 / 300 мс, `cubic-bezier(0.2, 0.8, 0.2, 1)`, spring-пружина
  для тактильного отклика нажатий.
- **touchTarget**: минимум 48×48 px.
- **shadow**: мягкие (прозрачность ≤ 0.3, радиус 14), без жёстких границ.

### Палитра и обоснование

| Токен      | Светлая                         | Тёмная    | Обоснование                                                                                                                                  |
| ---------- | ------------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| background | `#F7F4EE`                       | `#161917` | Тёплая «бумага» вместо чисто белого — не слепит в тёмной машине; тёмная тема — тёплый графит без синевы, чтобы не била по глазам в 4 утра    |
| primary    | `#2D6A4F`                       | `#7BC496` | Тёмно-зелёный: рыночный, спокойный, цвет урожая и весов. Не «банковский» синий и не тревожный красный. В тёмной теме — светлее для контраста |
| warning    | `#DE911D` (+ текст `onWarning`) | `#E0AC4E` | Мягкий янтарный: «поторопись», но не «опасность». **Красный запрещён**: в 4 утра он считывается как тревога и ошибка                         |
| text       | `#212A24`                       | `#EFEDE7` | Тёплые оттенки серо-зелёного вместо чисто чёрного/белого                                                                                     |

Контрасты (WCAG 2.1, посчитаны для всех пар текст/фон): основной текст — 13–15:1 (AAA),
тексты кнопок и бейджей — 6.4–11.6:1 (AA–AAA), вторичный текст ≥ 6.7:1.
Полная таблица — [docs/design/palette.md](../design/palette.md).

### Тёмная тема — с первого дня

- Дефолт — «как в системе» (`useColorScheme`), плюс ручной переключатель
  на каждом экране (круглая кнопка 48×48 рядом с заголовком).
- Все компоненты берут цвета только через `useTheme()` — прямые hex-значения
  в экранах запрещены.

### Компоненты

`Text`, `Button`, `Card`, `Input`, `Badge`, `Screen` (safe-area-обёртка).
Кнопки — pill-формы, высота 48/56 px, spring-отклик (Reanimated `withSpring`,
масштаб 0.97). Ошибки полей — янтарным, не красным.

## Рассмотренные альтернативы

- **Tamagui / NativeBase** — мощные, но тянут собственную runtime-тему и стили;
  для 6 компонентов этапа «фундамент» это лишний слой, который потом сложнее менять.
- **Только нативные компоненты без дизайн-системы** — на следующих этапах
  (брони, заказы, долги) экраны расползутся по стилям.
- **Красный для ошибок** — стандарт для веба, но противоречит философии «не тревожить
  в 4 утра»; решение: ошибки и срочность — янтарные, катастрофы (нет сети и т.п.) —
  текстом и нейтральной тональностью.

## Последствия

- ✅ Один источник токенов: смена палитры = правка одного файла.
- ✅ WCAG AA на всех читаемых сочетаниях — утренняя читаемость на улице.
- ⚠️ Требуется дисциплина: новые компоненты только поверх `useTheme()`.
- ⚠️ Известный нюанс web-экспорта: `@expo/vector-icons` при статическом SSR рендерит
  пустой текст, пока шрифт не загружен, — React логирует recoverable-ошибку гидрации
  и перерисовывает на клиенте (визуально корректно, нативные приложения не затронуты).
  Апстрим-проблема expo, отслеживаем; на нативную сборку не влияет.
