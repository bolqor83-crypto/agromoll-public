# ADR-030: Тёмная тема и адаптивность

- Статус: **Принято**
- Дата: 2026-11-07
- Этап: v0.6.2 «Design & UX Excellence» (подэтап D)
- Связанные: ADR-002 (дизайн-система), ADR-014 (карта рынка),
  ADR-024 (скругления/keyboard), ADR-028 (типографика и карточки),
  AUDIT-v0.6.2.md (пункты 5, 6, 14, 15, 16, 21)

## Контекст

Аудит v0.6.2 (подэтап A) зафиксировал четыре группы проблем за пределами
типографики и карточек (закрыты в B):

1. **Hardcoded-цвета вне токенов** (№5): 15 хексов в 6 файлах — карта
   (маркеры/канва/сетка), выбор ТС при публикации маршрута, выбор точек
   доставки, QR, +html. В тёмной теме чипы выбора «светились бумажным»
   цветом (#D8D2C6/#E7F0E9 на графитовом фоне).
2. **Карта только для светлой темы** (№6): web-канва #EAF0E8 в тёмной
   теме выбивается светлым пятном; янтарный коридор #C98A2D на канве —
   контраст 2.53:1, ниже порога WCAG 1.4.11 для графики (3:1).
3. **Scrim модалок-листов слабый** (№14): 0.45 (light) / 0.6 (dark) —
   лист недостаточно отделяется от контента; спека этапа — 0.7.
4. **Нет адаптивности** (№15/№16): `supportsTablet: true` в app.json,
   но ни одного breakpoint'а в коде — на планшете ≥768px лента в одну
   колонку (карточка ~730px, строки >90 символов), на больших телефонах
   ≥430px контент растянут на всю ширину (60+ символов в строке).
   Таб-бар растягивается на 4 вкладки по ~190px. Плюс мелочь (№21):
   web-скроллбар системный, вне темы.

Контраст текста тёмной темы уже AA после подэтапа B (textMuted 4.62:1,
янтарь 7.73:1, зелёный primary «не светится» — 7.73:1 на surface);
закреплён программным тестом `packages/ui/src/contrast.test.ts`.

## Решение

### 1. Палитра карты — семантические токены `mapPalette`

Новый экспорт tokens.ts: `MapThemeColors` (buyerPoint / sellerLine /
corridor / canvas / grid / centerRing / pinHole) + `mapPalette.light|dark`
+ `markerColorFor(kind, colors)`. `MapCanvasProps` получил **обязательные**
пропы `colors` и `mode` — забыть тему стало невозможно типами.

| Роль          | light            | dark          | Примечание                              |
| ------------- | ---------------- | ------------- | --------------------------------------- |
| buyerPoint    | #3B6FA0 (4.57:1) | #7FA8CC (6.4:1) | синий — семантика «куда везти» (v0.5.0) |
| sellerLine    | #2D6A4F (=primary) | #7BC496 (=primary) | линия продавца следует теме          |
| corridor      | #A8731B (3.53:1) | #E0AC4E (=warning) | **было #C98A2D — 2.53:1, FAIL 1.4.11** |
| canvas        | #EAF0E8          | #1E2320 (=surface) | тёмная карта больше не «светлое пятно» |
| grid          | #D8E2D4          | #333A34 (=border) | декоративная сетка улиц               |
| centerRing    | #4A4A44 (7.7:1)  | #868C82 (4.6:1) | позиция пользователя — значимая графика |
| pinHole       | #FAF8F4          | #1E2320       | сердцевина пина «моя точка»             |

- Web (SVG-карта): все элементы красятся из пропа — фон, сетка, маркеры,
  кольцо, пин.
- Native (react-native-maps): pinColor/Polyline из пропа; на iOS
  `userInterfaceStyle={mode}` переключает системные тайлы (iOS 13+).
  Стилизация Google-тайлов на Android (customMapStyle) — вне этапа:
  требует визуальной проверки на устройстве, рисковать вслепую нельзя.
- Легенда «Обозначения» и чипы выбора ТС (карта, «Заказать доставку») —
  из тех же токенов (`colors.primary/border/primaryMuted`): в тёмной теме
  ничего не «светится бумагой».
- Контраст маркеров ≥3:1 к канве в обеих темах закреплён тестом
  (`contrast.test.ts`, раздел WCAG 1.4.11).

### 2. QR — токены светлой темы как стандарт сканирования

QR-код технически обязан быть тёмным на светлом (сканеры). Цвета берутся
из `palette.light` (surface/text) — из токенов, но вне зависимости от
темы приложения: код сканируется и днём, и в тёмной теме.

### 3. Scrim 0.7

`palette.*.scrim`: light `rgba(15,20,17,0.7)` (было 0.45), dark
`rgba(0,0,0,0.7)` (было 0.6) — единая глубина в обеих темах, лист
читается как слой поверх контента. Закреплено тестом (парсинг альфы).

### 4. Адаптивность

Константы в tokens.ts (`responsive`): `tabletMinWidth 768`,
`widePhoneMinWidth 430`, `contentMaxWidth 600`. Хук `useResponsive()`
(экспорт ui-пакета) — единая точка решений.

- **Screen (все 17 экранов)**: на ≥430px контентная колонка
  `maxWidth 600 + alignSelf center`; фон заливается на всю ширину —
  колонка не выглядит «вклеенной». Опт-аут — `maxContentWidth={false}`
  (для полноширинных карт). На телефонах <430px — без изменений.
- **Лента и витрина**: на ≥768px — 2 колонки (flexWrap, карточки 48.5%,
  columnGap/rowGap 12 из сетки отступов); телефон — одна колонка как
  раньше. Карточка в колонке ~260px — комфортная ширина строки.
- **TabBar**: на ≥430px — тот же кап 600 по центру, в одной линии с
  контентной колонкой Screen; вкладки не растягиваются по ~190px.
- Число колонок в сетках — `cardColumns` из хука (2 на планшете).

### 5. Web-скроллбар из токенов

RN не умеет красить скроллбары. ThemeProvider на web пишет CSS-переменную
`--agromoll-scrollbar = colors.borderStrong` и `color-scheme = mode` на
`<html>`; `+html.tsx` красит скроллбары через переменную (thin,
border-radius 999, прозрачный трек). Бонус `color-scheme`: системные
контролы браузера (инпуты, календари) следуют теме. theme-color и
focus-обводка в `+html.tsx` — из `palette` (импорт токенов, не хардкод).

### 6. Что НЕ менялось (границы подэтапа)

- **Двойной боковой отступ списков** (Screen padding 16 + собственный
  padding экрана = 32px у карточек): существует со времён v0.6.1,
  равномерен на всех экранах, лежит на сетке отступов (32) и визуально
  принят аудитами. Менять семантику padding у 17 экранов — риск
  регрессий без запроса пользователя; при желании — отдельный шаг.
- **Pull-to-refresh** уже зелёный из токена `primary` (v0.6.1).
- **KeyboardAvoidingView**: все инпуты живут в SheetModal (KAV внутри,
  ADR-024); инлайн-инпутов на экранах нет (state maxWeight на карте
  рендера не имеет — остаток v0.5.0, не трогаем: бизнес-логика).
- Яркость янтаря/зелёного в тёмной теме — уже AA после B, не трогаем.

## Тесты

- `packages/ui/src/tokens.test.ts` (+4): breakpoints, scrim 0.7
  (парсинг rgba), полнота и различность mapPalette, markerColorFor.
- `packages/ui/src/contrast.test.ts` (+3): все маркеры/кольцо/пин ≥3:1
  к канве в обеих темах (WCAG 1.4.11).
- `apps/mobile/src/lib/responsive.test.tsx` (новый, 8): Screen
  375/430/1024/maxContentWidth=false/scroll=false, useResponsive,
  TabBar 375/1024. Техника: `jest.spyOn(require('react-native'),
  'useWindowDimensions')` — `import * as` с babel-интеропом даёт копию
  namespace (spy патчит копию, компоненты читают оригинал), а фабричный
  jest.mock c requireActual обходит моки jest-expo (TurboModule crash).
- `FeedScreen.test.tsx` (+2): планшет 1024 — сетка row+wrap, обёртка
  карточки 48.5%; телефон 375 — колонка без сетки.

Прогон: lint / typecheck / test (161 mobile + 47 ui) / build зелёные.

## Последствия

- Плюсы: карта, чипы, QR, скроллбары и chrome браузера следуют теме;
  планшет и большие телефоны получают «приложение, а не растянутый
  телефон»; контраст графики карты закреплён тестом; hardcoded-хексов
  вне tokens.ts не осталось (grep-чисто).
- Минусы/риски: native-тёмная карта на Android — системные светлые
  тайлы (маркеры контрастны, канва — карта Google); стилизация —
  отдельная задача. Проценты 48.5% в сетке рассчитаны на капнутую
  колонку 600px; при изменении contentMaxWidth пропорция самокорректируется.
