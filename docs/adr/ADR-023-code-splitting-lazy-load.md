# ADR-023: Code splitting по маршрутам — React.lazy в тонких файлах маршрутов

- Статус: **Принято**
- Дата: 2026-11-06
- Этап: v0.6.1 «Mobile UX Excellence» (подэтап A)

## Контекст

Инвентаризация (v0.5.0): web-бандл монолитный — 526 КБ gzip / 2.16 МБ raw,
один entry-чанк, ноль динамических импортов по маршрутам (единственные
`import()` — outbox-хранилища). TTI 4.2 с на «среднем устройстве»
(4×CPU + Fast 3G). Код всех ролей грузится до первого экрана.

## Решение

### Механизм: тонкие маршруты + React.lazy + свой Suspense

- Файл маршрута в `app/` — обёртка из `lazyScreen(() => import('@/screens/X'))`
  (новый хелпер `src/lib/lazy-screen.tsx`).
- Код экрана — в `src/screens/*Screen.tsx`, Metro при `expo export` кладёт
  его в отдельный чанк (splitChunks для `import()` уже подтверждён
  outbox-чанками v0.5.0).
- Пикер ролей (`app/index.tsx`) и экран входа (`app/auth.tsx`) — в главном
  чанке: первый экран сессии, размер пренебрежим.
- Общие экраны (DebtsScreen, WorkHoursScreen, MarketMapScreen) остались
  в `src/components` и подключаются так же лениво.

**Почему не `extra.router.asyncRoutes` expo-router (вариант из спеки
«expo-router lazy: true»):** режим работает (проверено экспериментально:
24 чанка), но (а) Suspense-фолбэк в expo-router 4.0 захардкожен — в prod
рендерится `null` (TODO в их коде, API кастомизации нет) — это нарушает
требование «Skeleton-карточки, не спиннер и не пустота»; (б) пикер ролей
уходит из главного чанка. Свой React.lazy+Suspense даёт полный контроль
фолбэка и не зависит от внутренностей роутера. Собственный вариант —
первый в спеке («React.lazy + Suspense»).

### Фолбэк — Skeleton-каркас

`ScreenSkeleton`: заголовок-скелет + 3 SkeletonCard (вариант `cards`
для лент) либо крупные блоки (`plain` для деталей: лот, рейтинг, очередь).
Никаких спиннеров — философия ADR-009. Каркас объявляется скринридеру
(`accessibilityLabel="Экран загружается"`).

### Изоляция ролей + prefetch

- Код роли грузится только при переходе в неё: чанки вкладок покупателя
  не тянут код продавца/доставщика (проверено в браузере: в сессии
  покупателя грузились только buyer-чанки).
- Лейаут роли на маунте прогревает свои вкладки (`src/lib/prefetch.ts`):
  первый переход по любой вкладке — без сетевой паузы; чанки по 1–5 КБ
  gzip.

### Убранные из главного чанка

- **react-native-gesture-handler (~383 КБ raw)** — side-effect импорт из
  root-layout уходил в web-бандл. Платформенное расширение
  `src/lib/gesture-handler-boot.{ts,native.ts}`: на web пусто, на native
  импорт остался.
- **expo-location (32 КБ raw)** — общий для трёх чанков (лента, доставка,
  карта): Metro поднимает модули, используемые ≥2 асинхронными чанками,
  в entry. Переведён на динамический импорт внутри обработчиков
  (паттерн NetInfo из v0.3.0).
- **Баррель `@/components`** — любой импорт из индекса исполнял ВСЕ
  компоненты; Barrel вычищен, все импорты по прямым путям.

## Замеры (методика инвентаризации: 4×CPU + Fast 3G, холодный контекст)

Playwright + CDP, локальный gzip-сервер, 3 прогона, медиана.
Маркер TTI — лог `приложение запущено` из RootLayout (React смонтирован).

| Метрика | до (v0.6.1-0) | после (A) | Δ |
|---|---|---|---|
| entry-чанк (gzip) | 519 КБ | **437 КБ** | −16% |
| чанков на первый экран | 1 (монолит) | entry + 1–2 служебных | экраны по 1–5 КБ |
| TTI, локальный замер | 3710 мс | **3235 мс** | −13% |
| TTI, против инвентаризации (4.2 с) | — | 3235 мс | −23% |
| Переход по вкладке роли | — | чанк прогрет prefetch | мгновенно |

## Отклонение от цели и его причины

Цель «entry < 300 КБ gzip, TTI < 2.5 с» **не достигнута** и в рамках
подэтапа недостижима: после всех вычисток entry состоит из фреймворк-пола:
react-native-web (~733 КБ raw), react-native-reanimated (~570, дизайн-система
построена на нём), expo-router (~293), react-navigation (~395 суммарно),
react-dom (~135), axios (~191) + zod (~146) — api-клиент нужен на буте
(refresh сессии), React.lazy здесь не помогает, т.к. сторы в root-layout
синхронны. Metro не делает tree-shaking — «вырезать» неиспользуемое из
RNW/reanimated нельзя.

Варианты дальнейшего сокращения (вне скоупа A, для решения владельцем):

1. **axios → fetch** (−~25 КБ gzip): переписать ядро api.ts (интерцепторы,
   single-flight refresh, маппинг ошибок) + тесты. Риск средний.
2. **Ленивая загрузка zod-схем** (−~20 КБ): `await import('@agromoll/validation')`
   в apiRequest — ~60 точек, гонки на первом ответе. Риск средний.
3. **Отказ от reanimated в ui на web** (−~80 КБ): переработка анимаций
   дизайн-системы на CSS-transition. Большой редизайн.
4. Brotli на Vercel даёт ещё −10–15% к gzip-размерам автоматически.

По стоп-правилу 3 (< 20% прироста TTI) вопрос вынесен владельцу: локально
честный прирост −13% (против инвентаризационных 4.2 с — −23%).
