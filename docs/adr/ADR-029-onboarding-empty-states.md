# ADR-029: Онбординг и пустые состояния

- Статус: **Принято**
- Дата: 2026-11-07
- Этап: v0.6.2 «Design & UX Excellence» (подэтап C)
- Связанные: ADR-002 (дизайн-система), ADR-005 (визуальные компоненты),
  ADR-009 (визуальные паттерны), ADR-026 (честный демо-режим),
  ADR-027 (анимации), AUDIT-v0.6.2.md (проблемы №17–19)

## Контекст

Аудит v0.6.2: (1) онбординга нет — новый пользователь попадает в выбор роли,
не понимая ценности приложения; (2) пустые состояния статичны после
появления, у трёх нет действия; (3) первый вход в роль без подсказок —
пользователь ищет глазами, где брони и как создать лот.

## Решение

### 1. Онбординг — 3 слайда, после выбора роли

**Почему 3, а не больше.** Три главные ценности продукта покрываются
ровно тремя экранами: закупка (лента лотов) → доставка (попутчики) →
доверие (рейтинг). Четвёртый слайд — риск, что пользователь начнёт
пролистывать не читая; в 4 утра читают плохо.

**Почему после выбора роли, а не до.** Роль — первый осмысленный выбор
пользователя; до него «Закупайтесь быстрее» — абстракция. После выбора
слайды ложатся на уже понятный контекст («вы покупатель — вот лента»).
Бонус: heбоardинг не стоит между логином и ролями у повторных пользователей.

Поток: `index (выбор роли)` → `onboarding?next=<route роли>` → экран роли.

- Свайп между слайдами (`ScrollView pagingEnabled`) или кнопка «Далее»;
  на последнем слайде — «Начать».
- «Пропустить» доступен с первого слайда — онбординг не блокирует вход
  (философия этапа: простота, не разворот).
- Иллюстрации — геометрические композиции в токенах (как EmptyState):
  стопка карточек лотов, грузовик на маршруте A→Б, звезда рейтинга со
  шкалой. Никаких стоковых картинок (ADR-005).
- Точки-индикатор: активная растягивается в пилюлю (spring).

**Флаг первого запуска** — `agromoll.onboarding.v1` в
AsyncStorage (native) / localStorage (web), тот же адаптер, что у настроек
(ADR-024). Ключ версионируется: смена формата онбординга → v2, все увидят
обновлённые слайды один раз. Пишется при завершении («Начать» или
«Пропустить»): прерванный показ честно повторится. При ошибке чтения
флага — не показываем (лучше без онбординга, чем заблокированный вход).

### 2. Пустые состояния: живые иллюстрации + действие

- **Idle-анимации** (после staggered-появления, ADR-027): корзина
  покачивается ±2°, ящик «дышит» (1→1.04), точка радара поднимается,
  календарь плывёт ±2px, **грузовик катится** ±5px с наклоном — период
  2.8 с, repeat, амплитуды тихие: заметно периферийным зрением, не
  отвлекает. Reduced motion — статично (как у всех анимаций, ADR-027).
  Трансформации — чистая функция `idleTransformFor(kind, t)` (тестируемая).
- **Новая иллюстрация `truck`** — для экранов доставок: кузов + кабина +
  колёса + дорога штрихами.
- **Конкретное действие у каждого состояния** (аудит №18):
  - радар: «Обновить» (новое);
  - мои доставки: «В радар» (новое) + иллюстрация truck;
  - доставка покупателя: «Создать запрос» (новое, открывает шторку) + truck;
  - лента «Обновить», брони «В ленту», входящие «Обновить», часы и долги —
    уже были, не тронуты.

### 3. Coach marks — подсказки первого входа в роль

По 2 подсказки на роль (покупатель: брони + «Рядом»; продавец: «+» для
лота + входящие; водитель: радар + мои доставки). Формат — плашка над
таб-баром: иконка + 1 строка + крестик.

- **Не блокируют**: нет scrim, `pointerEvents="box-none"` вне плашки —
  интерфейс под рукой полностью живой.
- Показ один раз: флаг `agromoll.coachmark.<role>` (тот же адаптер).
  Роли изолированы — смена роли показывает свои подсказки один раз.
- Тап — скрыть (пишет флаг); авто-смена на вторую подсказку через 7 с,
  после второй — авто-скрытие.
- Вход: slide-up + fade spring; смена подсказки — мягкий свап (fade 120 мс
  + spring).

## Последствия

- +1 маршрут `/onboarding` (вне групп ролей), +2 компонента
  (RoleCoachMark, lib/first-run), EmptyState расширен без ломки API
  (новый illustration kind + опциональная idle-анимация).
- Тесты: first-run (флаги и изоляция ролей), onboarding (3 слайда,
  пропуск, «Начать», переход на next), RoleCoachMark (один показ, тап,
  изоляция), EmptyState (truck + чистые idle-трансформации).
- Онбординг не показывается повторным пользователям v0.6.1 (флаг
  пишется впервые в v0.6.2) — новая фича видна всем один раз, это
  осознанно: слайды объясняют и доставку, и рейтинг (v0.5.0+).
