# ADR-027: Анимации и переходы

- Статус: **Принято**
- Дата: 2026-11-06
- Этап: v0.6.1 «Mobile UX Excellence» (подэтап E2 — приоритет пользователя,
  не «вишенка»)

## Контекст

Функциональность v0.6.1 (0–E) закрыла честность и удобство, но интерфейс
«щёлкает»: вкладки переключаются мгновенно (53–80 мс без анимации),
счётчики меняются скачком, ошибки и успех происходят «тихо». Философия
продукта (ADR-009): рынок в 4 утра, одной рукой, в перчатках — движение
должно ОБЪЯСНЯТЬ, что произошло, а не развлекать.

Требования: всё на Reanimated 3 (уже в проекте, без новых зависимостей),
длительности 200–300 мс из токенов, spring-характер, обязательный
prefers-reduced-motion, FPS не ниже 45 при скролле.

## Решение

### Почему Reanimated 3, а не альтернативы

- Уже в зависимостях (дизайн-система с v0.3.1) — нулевой вес в bundle.
- Анимации на UI-потоке: не блокируют JS при скролле и не дёргаются
  при загрузке данных.
- `react-native-reanimated` официально поддерживает react-native-web —
  те же анимации работают в web-версии на Vercel.
- Отказ от react-native-screen-transitions / navigation shared-element —
  обоснован в ADR-009: глобальная инфраструктура ради 60 строк кода.

### Почему spring и 200–300 мс

Spring (а не easing-кривые) — физическая модель: быстрый разгон,
мягкая остановка, как настоящие предметы. Длительности — из токенов
`motion` (fast=200, normal=300): короче 200 мс глаз не успевает
прочитать движение, длиннее 300 мс — раздражает в рабочем цикле.
Исключения задокументированы: счётчики и success — 400 мс (надо успеть
увидеть число/факт), shake — 300 мс суммарно (4×75 мс).

### 1. Переходы между вкладками (TabScreenMotion)

bottom-tabs держит посещённые экраны смонтированными и скрывает
исходящий мгновенно — анимировать mount бесполезно. Решение: обёртка
`TabScreenMotion` внутри `lazyScreen` (над границей Suspense — prefetch
и ленивые чанки ADR-023 не затронуты):

- входящий экран — opacity 0→1 + translateX 8→0, 200 мс;
- триггер — ПОЯВЛЕНИЕ ФОКУСА (`useIsFocused`), не mount: вкладка
  «вплывает» при каждом переключении;
- исходящий — скрыт навигатором мгновенно: честное ограничение
  bottom-tabs (анимация исходящего требует форков), входящая анимация
  закрывает визуальный «вакуум»;
- первый вход — после Suspense-скелета анимируется появившийся контент
  (обёртка внутри Suspense).

### 2. Морф карточки → детальный экран

Переиспользован паттерн v0.3.1 (ADR-009): карточка замеряет себя
(`measureInWindow` → `recordTransitionOrigin`), детальный экран забирает
фрейм одноразово и spring-ом (damping 18 / stiffness 220) «вырастает»
из него. Добавлен respect reduced motion (морф мгновенный).

Карточка долга → «детали долга»: морф НЕ реализован, потому что
детального экрана долга нет — действия (погасить/спор/напомнить) живут
в самой карточке (ADR-010). Морф без цели — пустая трата кадров.

### 3. SuccessCheck — тихая галочка успеха

Зелёная галочка в круге: scale 0→1.1→1 + opacity 0→1, 400 мс spring,
haptic success(). Показывается ~1 с поверх карточки/экрана, затем
родитель убирает (onDone). Не конфетти, не салют (ADR-002). Точки:
принятие корректировки брони (покупатель), подтверждение брони
(продавец), погашение долга / обоюдное закрытие спора, опустошение
очереди outbox (мини-галочка в ConnectionBadge: «всё отправлено»).

### 4. ShakeField — покачивание при ошибке валидации

translateX 0→−4→4→−4→0 (4×75 мс = 300 мс) + haptic warning. Триггер —
инкрементируемый `shakeKey` от родителя, когда значение ПОСЛЕ валидного
стало невалидным (сумма долга > лимита, цена/количество лота, вес
доставки > 20 000 кг). Только локальные ошибки валидации: сетевые
ошибки — ErrorState (ADR-026), их не «трясут».

### 5. Появление ErrorState и EmptyState

Блок целиком: scale 0.95→1 + opacity 0→1, 300 мс spring; иллюстрация —
на 100 мс позже (staggered: глаз ведёт от общего к деталям). Раньше
появлялись мгновенно, а EmptyState анимировал только иллюстрацию.

### 6. AnimatedNumber — плавный пересчёт чисел

Прогресс 0→1 на UI-потоке (withTiming 400 мс), интерполяция
старое→новое в useDerivedValue, текст — через useAnimatedReaction +
runOnJS (форматирование/Intl — работа JS-потока, в ворклете нельзя).
Финальное значение синхронизируется эффектом: корректность важнее
анимации. Точки: суммы долгов (виджет), часы пар (289-ФЗ), рейтинг.
Движение числа само говорит «на сколько изменилось».

### 7. Пульсация офлайн-индикатора

Уже была (opacity 1→0.6→1, 2 с) — не тронута.

### Reduced motion — обязательный

Все новые анимации читают `useReducedMotion()` из Reanimated
(системная настройка / prefers-reduced-motion на web): движение
заменяется мгновенным появлением, стартовые значения shared values
инициализируются «видимыми» (ни одного пустого кадра). Haptic остаётся —
тактильность не движение. Для тестируемости компоненты принимают
`reducedMotion`-проп поверх системного значения.

## Замеры FPS (методика README: 4×CPU, колесо 5 с, 12 лотов, медиана 3)

| Сборка               | Холодные прогоны | Разогретые прогоны |
| -------------------- | ---------------- | ------------------ |
| v0.5.0               | 53.4 / 58.2      | 60.0 (vsync)       |
| v0.6.1-D (до E2)     | 50.8 / 56.2      | 60.0 (vsync)       |
| v0.6.1-E2 (анимации) | 54.0 / 57.8      | 60.0 (vsync)       |

Чередованные замеры A/B/A/B: разница между версиями в одинаковых
условиях ≤ 0.4 FPS — в пределах шума песочницы. Регрессии нет:
при скролле ни одна новая анимация не исполняется (все — на появление
экрана/значения). Порог 45 не достигается даже в холодных прогонах.

## Тестирование

Мок Reanimated исполняет анимации мгновенно и не содержит
useReducedMotion (добавлен в jest.setup) — поэтому unit-тесты проверяют
СТРУКТУРУ и решения, а не кадры: рендер SuccessCheck/AnimatedNumber/
ShakeField/TabScreenMotion, testID и a11y-метки, доехавшее до финала
значение AnimatedNumber, переключение фокуса TabScreenMotion. Визуальная
плавность подтверждена двухкадровыми скриншотами (кадр «в движении» +
финал) и FPS-замерами.

## Последствия

- Все переходы объясняют действие, ни одна анимация не длиннее 400 мс.
- `lazyScreen` остаётся единственной точкой входа маршрутов: переходы
  вкладок не нужно добавлять в каждый экран.
- Entry-чанк +1.6 КБ gzip (444.5 КБ), чанков по-прежнему 17.
- Счётчики показывают финал даже если анимация не успела — данные
  никогда не врут ради красоты.
