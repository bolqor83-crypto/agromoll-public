# ADR-025: Primary actions в thumb zone + доступность

- Статус: **Принято**
- Дата: 2026-11-06
- Этап: v0.6.1 «Mobile UX Excellence» (подэтап C)

## Контекст

Инвентаризация: primary-действия разбросаны по экрану — «Получить код»
y=376 (центр), «Заказать доставку» y=190 (верх), «Беру» y=307. Рынок
работает одной рукой (вторая — держит товар/тележку), часто в перчатке:
главное действие должно жить в нижней трети, куда достаёт большой палец.
Плюс: иконка «+» без aria-дубля, отсутствие фокус-стилей на web.

## Решение

### Позиции primary actions (замер Playwright, окно 390×844)

Цель: центр кнопки в нижней трети (y > 557). Результаты после правок:

| Экран | Действие | Было | Стало (центр y) |
|---|---|---|---|
| Вход (телефон и код) | «Получить код» / «Войти» | 376 | **770** — форма сверху, кнопка прижата к низу |
| Доставка (покупатель) | «Заказать доставку» | 190 (под шапкой) | **603** — снизу экрана, всегда видна |
| Витрина (продавец) | FAB «Выставить лот» | 543 | **607** — у нижней кромки (offset 76→12) |
| Радар (доставщик) | «Беру» | 307 (в карточке) | карточка **осталась** (контекстное действие) + sticky «Беру · первый заказ» внизу — **651** |
| Долги | «Записать долг» | 580 | без изменений (внизу контент-зоны, вне скролла; в демо-режиме скрыт — записи без сервера нечестны) |
| Подтверждение приёмки | «Подтвердить получение» | в потоке | **footer-слот SheetModal**: прибита к низу листа, не «плавает» |

### Механика

- **SheetModal.footer** — новый опциональный слот: контент листа
  скроллится, футер (primary-кнопка) прибит к низу с бордюром. Первым
  использован в ConfirmDeliveryModal; в форму кнопка больше не входит.
- **Радар**: sticky-кнопка внизу действует на первый (ближайший) заказ
  списка — «Беру» одной рукой, не дотягиваясь до карточки. Кнопка в
  карточке сохранена — это действие конкретного заказа.
- **Вход**: Screen flex-макет — шапка и поле сверху, кнопка внизу
  (KeyboardAvoidingView из B не конфликтует: клавиатура поднимает кнопку).
- **Доставка**: контент-зона flex:1 (скелет/пусто/список), кнопка ниже —
  во всех состояниях прижата к низу.

### Иерархия и размеры (без изменений — уже соответствовали)

Button дизайн-системы: primary — зелёная заливка, lg = 56 px (спека
«min height 56»); secondary — мягкая зелёная; ghost — прозрачная с
рамкой. Destructive-действия — янтарный, не красный (ADR-002). Тач-зона
от 48 px (touchTarget.min).

### Доступность

- **Скан иконочных кнопок** — новый сторожевой юнит-тест
  (`icon-buttons-a11y.test.ts`): статически проверяет все Pressable с
  `<Icon>` и без текстовых детей на наличие `accessibilityLabel`
  (app/, src/components, src/screens). Текущий код чист — все иконки
  уже подписаны (ThemeToggle, ConnectionBadge, FAB «Выставить лот»).
- **Фокус-стили web** — `app/+html.tsx` (кастомный HTML-корень экспорта):
  `:focus-visible` обводка акцентом #40916C — видна только при
  клавиатурной навигации, тап не подсвечивает. Плюс `theme-color` и
  `-webkit-tap-highlight-color: transparent`. Нативные платформы файл
  не используют.

## Альтернативы

- Глобальный bottom-sheet-подход (все primary в системной панели внизу) —
  больше redesign, чем требует задача; отложено до v0.7.
- react-native-portal / floating-action библиотеки — лишняя зависимость,
  absolute-positioning внутри Screen решает то же.

## Последствия

- SheetModal API расширен опциональным footer — обратная совместимость
  полная (не передан — рендер как раньше).
- Скриншоты: `docs/screenshots/v0.6.1/C-{auth-button-bottom,delivery-button-bottom,showcase-fab,radar-sticky-take}-{light,dark}.png`.
- Замер «y > 600» из спеки уточнён до «центр в нижней трети»
  (y > 557 при 844): нижние 600px занимает ещё и панель вкладок (83px),
  кнопка не может быть ниже контент-зоны.
