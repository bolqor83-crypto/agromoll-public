# ADR-022: Конфигурация API URL — env вместо молчаливого localhost

- Статус: **Принято**
- Дата: 2026-11-06
- Этап: v0.6.1 «Mobile UX Excellence» (подэтап 0 — хотфикс прода)

## Контекст

Прод-сборка web-версии на Vercel (https://agromoll-web.vercel.app)
ходила на `http://localhost:3000/auth/*`: в `apps/mobile/src/lib/api.ts`
адрес вычислялся как

```ts
const API_URL = process.env.EXPO_PUBLIC_API_URL ?? 'http://localhost:3000';
```

Переменная `EXPO_PUBLIC_API_URL` нигде на проде задана не была (в Vercel
Project Settings env-переменных нет), поэтому фолбэк попадал в бандл.
Вне машины разработчика API на localhost мёртв: вход невозможен,
все экраны падают в network-error → демо-режим. Приложение на проде
«работало» только как витрина демо-данных.

Инвентаризация UX подтвердила факт: в entry-чанке прода
(`entry-d1d394...js`, 525 КБ gzip) строка `http://localhost:3000`
зашита на этапе сборки.

## Решение

### Один источник правды: EXPO_PUBLIC_API_URL

Новый модуль `apps/mobile/src/lib/api-config.ts`:

```ts
resolveApiUrl({ url, isDev }):
  url задан (после trim)  → нормализованный адрес (без хвостовых «/»)
  url не задан, isDev     → 'http://localhost:3000'   // dev-фолбэк
  url не задан, prod      → null                      // фолбэка НЕТ
```

### Почему фолбэк остался только в dev

- **Dev**: разработчик клонирует репозиторий и запускает
  `docker compose up` + `pnpm dev` — API по умолчанию на
  `localhost:3000`. Требовать `.env` для первого запуска — лишний барьер.
- **Prod**: «какой-нибудь» адрес по умолчанию — это всегда чей-то
  localhost или чужой домен. Оба варианта хуже честного «не настроено»:
  пользователь видит непонятные network-ошибки или, хуже того, демо-данные,
  похожие на настоящие.

### Экран «Сервер не настроен» вместо молчаливого localhost

Если `IS_API_CONFIGURED === false`, корневой `app/_layout.tsx` рендерит
`ApiNotConfiguredScreen` и **не запускает** bootstrap/outbox — запросов
нет вообще. Экран объясняет, что произошло, и содержит шаги подключения
(поднять API → задать env → пересобрать). Философия ADR-002: это не ошибка
пользователя, экран не пугает — геометрическая иллюстрация «сервер и
несоединённый кабель», тёплая палитра.

Аптайм-защита в `api.ts`: `baseURL` при null — плейсхолдер
`http://api-not-configured.invalid` (TLD `.invalid` гарантированно не
резолвится). Недостижимо при живом гейте, но исключает «тихий» запрос
на чей-то localhost, если гейт обойдён.

### Связь с деплоем на Vercel

Expo инлайнит `EXPO_PUBLIC_*` в бандл **на момент сборки** — сменить
адрес в рантайме нельзя. Поэтому:

- `apps/mobile/vercel.json` явно прокидывает
  `EXPO_PUBLIC_API_URL=\"$EXPO_PUBLIC_API_URL\"` в buildCommand: значение
  берётся из Vercel Project Settings → Environment Variables;
- если переменная не задана, прод показывает экран «Сервер не настроен» —
  это ожидаемое состояние, пока нет публичного API;
- план перевода API на публичный хостинг — [docs/DEPLOY.md](../DEPLOY.md)
  (MVP сознательно остаётся на варианте «API у разработчика»).

## Альтернативы

- **Захардкодить прод-URL в коде** — адрес меняется без релиза, leaking
  окружения в репозиторий, dev/prod ветвление в коде. Отвергнуто.
- **Runtime-конфиг (`/config.json` рядом с бандлом)** — позволяет менять
  адрес без пересборки, но добавляет второй источник правды и гонку на
  старте (нужно ждать fetch до рендера). Отложено: когда появится
  публичный API с несколькими окружениями, вернуться.
- **Фолбэк на относительный путь (`/api`)** — работает только если API
  живёт на том же домене (Vercel rewrite). Пока API не на Vercel,
  превращается в запросы к самому SPA → HTML 200 → INVALID_RESPONSE.
  Учтено в DEPLOY.md как опция после переноса API.

## Последствия

- Юнит-тесты: `api-config.test.ts` — dev-фолбэк, prod-без-фолбэка,
  нормализация адреса (jest-модули переимпортируются с моками env/`__DEV__`).
- Смоук: сборка с `EXPO_PUBLIC_API_URL` содержит адрес в бандле; сборка
  без него рендерит «Сервер не настроен» (проверено локально экспортом).
  Нюанс: кэш трансформаций Metro не включает env в ключ — при смене
  адреса локальная пересборка требует `--clear` (добавлен в build-скрипт
  и в vercel.json; на Vercel окружение сборки всегда чистое).
- `.env.example` и README документируют переменную и оба способа задать
  её на Vercel (Project Settings — рекомендованный; правка vercel.json).
- Версия 0.6.1 поднимается в этом же коммите (`package.json`, `app.json`
  и все workspace-пакеты).
