# v0.8.0-B — Runbook: публичный API на Railway

> Статус: **ждёт RAILWAY_TOKEN** (стоп-правило №1). Все артефакты в репо:
> `railway.json`, ADR-040, правки `main.ts` (PORT/CORS_ORIGIN).
> Этот документ — точная последовательность команд; выполнять сразу после
> передачи токена. Затраты: ~15 минут (первый билд Nixpacks 5–10 минут).

## 0. Предусловия

- `RAILWAY_TOKEN` в окружении (Railway → Account → Settings → API Tokens,
  права на создание проектов и сервисов).
- Аккаунт Railway имеет доступный trial/план (Hobby: $5/мес, включает
  $5 использования — хватает на API + Postgres + Redis демо-нагрузки).

## 1. Логин и проект

```bash
npm i -g @railway/cli          # если ещё не установлен
railway login --token $RAILWAY_TOKEN
railway init                   # New project → имя: agromoll-api
# (в неинтерактивной среде: railway init --name agromoll-api)
```

## 2. Сервисы

```bash
railway add --database postgresql --variable DATABASE_URL   # managed Postgres
railway add --plugin redis --variable REDIS_URL             # managed Redis
```

PostGIS: плагин Railway PostgreSQL — стандартный образ; расширение
добавляется первой же миграцией (`CREATE EXTENSION IF NOT EXISTS postgis`
в init-миграции — работает, если суперпользователь; если permission
denied, выполнить вручную: `railway run psql $DATABASE_URL -c "CREATE EXTENSION IF NOT EXISTS postgis;"`).

## 3. Переменные API (Railway → Variables)

```bash
JWT=$(openssl rand -hex 32); JWT2=$(openssl rand -hex 32)
railway variables --set \
  "NODE_ENV=production" \
  "JWT_ACCESS_SECRET=$JWT" \
  "JWT_REFRESH_SECRET=$JWT2" \
  "JWT_ACCESS_TTL=15m" \
  "JWT_REFRESH_TTL=30d" \
  "BOOKING_TTL_MINUTES=30" \
  "DELIVERY_TTL_MINUTES=60" \
  "WORK_HOURS_MONTHLY_LIMIT=60" \
  "WORK_MONTHS_SERIES=6" \
  "BOOKING_AUTO_CONFIRM_HOURS=24" \
  "CORS_ORIGIN=https://agromoll-web.vercel.app" \
  "AUTH_DEMO_LOGIN=true"
```

`AUTH_DEMO_LOGIN=true` — демо-режим входа (см. v0.8.0-C/DEMO.md):
SMS-код фиксированный «000000» (шесть нулей), в логах помечен предупреждением.
Для боевого запуска после демо — выставить `false` (или удалить).

S3_* (фото/доказательства, ADR-036) — опционально; без них storage
использует data:-URL fallback, демо-фото — внешние URL.

## 4. Деплой

```bash
railway up                     # билд Nixpacks по railway.json, миграции в startCommand
railway status                 # ждём Deployed; при ошибке — railway logs
```

Проверка миграций (если нужно отдельно):

```bash
railway run pnpm --filter @agromoll/api exec prisma migrate status
```

## 5. Публичный домен

```bash
railway domain                 # выдаст https://agromoll-api-production-XXXX.up.railway.app
curl -i https://<домен>/health # → 200 {"status":"ok",...}
```

## 6. Связка с Vercel (ADR-022: URL вшивается в бандл на сборке)

```bash
# локально, токен Vercel из v0.7.0:
npx vercel env add EXPO_PUBLIC_API_URL production --token $VERCEL_TOKEN
# значение: https://agromoll-api-production-XXXX.up.railway.app
npx vercel deploy --prod --yes --token $VERCEL_TOKEN   # или redeploy в UI
curl -I https://agromoll-web.vercel.app                # → 200
```

## 7. Smoke-тест API

```bash
API=https://agromoll-api-production-XXXX.up.railway.app
curl -s $API/health | grep '"ok"'
curl -s -X POST $API/auth/request-code -H 'Content-Type: application/json' \
  -d '{"phone":"+79000000010"}'          # expiresInSec — код «0000» (демо)
curl -s -X POST $API/auth/verify -H 'Content-Type: application/json' \
  -d '{"phone":"+79000000010","code":"000000"}' | head -c 200   # accessToken
curl -s "$API/listings?limit=5" | head -c 300             # лоты из сида (v0.8.0-C)
```

## 8. Откат

- Railway → Deployments → предыдущий → Redeploy (ADR-040, раздел «Откат»).
- `npx vercel rollback agromoll-web --token $VERCEL_TOKEN` — откат фронта.
