# v0.8.0-A — Токены и среда (env-check)

> Подэтап A задачи v0.8.0 «Public Launch». Дата: 2026-11-07.
> Проверка токенов и локальной среды перед публикацией API, EAS-сборкой
> и локальным E2E-стендом.

## 1. Токены

| Токен | Есть? | Где нужен | Что делать |
|---|---|---|---|
| `VERCEL_TOKEN` | ✅ есть (из v0.7.0, передан пользователем) | Деплой web на Vercel, `vercel env add`, smoke-проверки | Ничего — уже в GitHub Secrets для `vercel-deploy.yml` и в локальном `.env` агента |
| `RAILWAY_TOKEN` | ❌ **нет** | Подэтап B: `railway login/init/add/up`, публичный API + Postgres + PostGIS + Redis | **Запрошен у пользователя.** Без него подэтап B не выполняется: подготовлена вся конфигурация и runbook, деплой — сразу после получения токена |
| `RENDER_API_KEY` (альтернатива Railway) | ❌ нет | То же, но на Render (fallback, если Railway не подойдёт) | Не запрошен — Railway приоритетен (у Railway есть managed Postgres с PostGIS и проще CLI) |
| `EXPO_TOKEN` | ❌ **нет** | Подэтап D: `eas login/init/build` (сборка .apk); подэтап E: `eas update` (публикация OTA) | **Запрошен у пользователя.** Без него: подготовлены `eas.json`, workflow OTA и документация; реальная сборка — сразу после получения токена |

Секрет `EXPO_TOKEN` в GitHub Secrets (для workflow `eas-update.yml`, подэтап E) —
ручной шаг пользователя: Settings → Secrets and variables → Actions →
New repository secret (Name: `EXPO_TOKEN`). Добавить можно параллельно с
передачей токена агенту.

**Стоп-правило №1 сработало:** RAILWAY_TOKEN и EXPO_TOKEN отсутствуют →
запрошены, работа продолжается на подэтапах, где токены не нужны
(C — расширение сида и DEMO.md; D/E — конфигурация и workflow; F —
локальный E2E-стенд; G — всё, что не требует живых Railway/EAS).

## 2. Локальная среда агента (E2E-стенд подэтапа F)

| Компонент | Статус | Комментарий |
|---|---|---|
| Node.js | ✅ v24.22.2 | Требование репо `>=20` выполнено |
| pnpm | ✅ 9.x через corepack | `packageManager: pnpm@9.15.9`; глобальный symlink недоступен (нет прав на `/usr/bin`) — используется `corepack pnpm` |
| git | ✅ 2.47.3 | Клон по PAT работает |
| Playwright + Chromium | ✅ установлен | Headless-браузер для прогона веб-флоу (подэтап F) |
| docker | ❌ нет | Права root отсутствуют (`sudo` требует пароль) — `docker compose up` невозможен |
| Redis | ⚠️ нет в системе | Решение: распаковка `.deb` (`apt-get download` + `dpkg -x`) без root — Debian 13, пакет `redis-server` доступен |
| Postgres + PostGIS | ⚠️ нет в системе | То же решение: `postgresql-17` + `postgresql-17-postgis-3` из репозитория Debian 13, распаковка без root в `/tmp/pg`, `initdb` + `pg_ctl` от имени пользователя `z`. PostGIS обязателен (`CREATE EXTENSION postgis` в init-миграции + geo-триггер, ADR-014) |
| Выход в интернет | ✅ | github.com, api.vercel.com, npm, deb.debian.org доступны |

**Вывод по стенду F:** docker отсутствует, но managed-БД не нужна —
Postgres 17 + PostGIS 3.6 и Redis 8 разворачиваются локально из пакетов
Debian без root. SQLite-fallback не используется (не поддерживает PostGIS).
Версии отличаются от CI-образа (`postgis/postgis:16-3.4`, Redis 7) —
локальный стенд прогоняет те же миграции Prisma, расхождение только
в минорных версиях движка, что для E2E-флоу некритично (задокументировано).

## 3. Состояние прода на момент A

- Web: https://agromoll-web.vercel.app — деплоится автоматически (ADR-032),
  отдаёт бандл 0.7.0, показывает «Сервер не настроен» — `EXPO_PUBLIC_API_URL`
  в проекте Vercel не задан, потому что API ещё не опубликован (это и есть
  задача v0.8.0-B).
- API: нигде не развёрнут (жил на машине разработчика). Публичного URL нет.
- Порядок: B (поднять API на Railway → получить URL) → прописать
  `EXPO_PUBLIC_API_URL` в Vercel → redeploy фронта (ADR-022: адрес вшивается
  в бандл на сборке, существующий деплой его не подхватит).

## 5. Открытые вопросы к пользователю

1. **Передать `RAILWAY_TOKEN`** (Railway → Settings → API Tokens; доступ
   нужен к аккаунту, где будут созданы проект `agromoll-api`, PostgreSQL
   и Redis) — блокирует подэтап B и частично C (прогон сида на боевой БД),
   G (публичные ссылки).
2. **Передать `EXPO_TOKEN`** (expo.dev → Account Settings → Access Tokens) —
   блокирует подэтап D (реальная сборка .apk) и проверку OTA из E.
3. **Apple Developer аккаунт** — по стоп-правилу №5: если нет, iOS-сборка
   пропускается с задокументированным ограничением (нужен аккаунт $99/год
   + UDID устройства для internal distribution).
