## 2. Почему Render + Neon (сводка; полный разбор — ADR-040 в подэтапе B)

- **Railway** — платформенный инцидент QBCLHG1V «External network blocks»,
  статус IDENTIFIED с 2026-11-05, деплои на паузе, стабильность не
  восстановлена. Прод не может ждать неопределённое время.
- **Render** — есть API-ключ, free tier для web-сервиса, IaC через
  `render.yaml` (Blueprint). Ограничение: спин-даун через 15 мин простоя,
  холодный старт 30–50 сек — приемлемо для демо, переход на Starter $7/мес
  снимает проблему.
- **Neon** — serverless Postgres 16, free tier не удаляется (в отличие от
  Render free Postgres — 30 дней), расширение PostGIS доступно на free
  (проверяется в подэтапе A после получения доступа).

## 3. Инструкция пользователю: Neon за ~3 минуты

1. https://neon.tech → **Sign up** (удобнее через GitHub-аккаунт).
2. **New Project** → имя `agromoll-api`, регион — ближайший (Frankfurt
   `aws-fra-1` для РФ/ЕС), Postgres 16.
3. На дашборде проекта → **Connection string** (формат
   `postgresql://user:pass@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require`)
   → прислать в чат (это и есть `DATABASE_URL`).
4. SQL Editor → выполнить `CREATE EXTENSION IF NOT EXISTS postgis;`
   (или пришлите строку — агент выполнит сам).

Альтернатива: создать API-ключ (Account → API Keys, формат `napi_…`) и
прислать его — тогда проект и БД создаст агент через
`POST https://console.neon.tech/api/v2/projects`.

Если PostGIS на Neon free окажется недоступен — переключение на Supabase
(аналогичная инструкция), фиксируется в ADR-040.
