## Деплой: что пришлось решить

### 1. Приватный репозиторий и GitHub App

Render **не клонирует приватные репозитории** без установленного на
GitHub-аккаунт Render GitHub App: `POST /v1/services` с приватным URL →
400 «invalid or unfetchable» (токен в URL не поддерживается). Подключение
App — ручной шаг в дашборде владельца, ждать его не стали.

**Решение**: публичное зеркало
[bolqor83-crypto/agromoll-public](https://github.com/bolqor83-crypto/agromoll-public)
(main + feature-ветки). Перед пушем — **аудит секретов всей git-истории**
(2322 объекта; паттерны napi_/rnd_/rlwy_/ghp_/AKIA/строки подключения):
реальных секретов нет, только плейсхолдеры `agromoll:agromoll@localhost`
(CI/testcontainers) и упоминание красacted-префикса в runbook. Продукт
демо-публичный (скриншоты, ссылки, демо-код уже наружу), так что зеркало
не меняет модель доступа. Зеркало синхронизируется пушем из основного
репо; когда владелец подключит GitHub App — сервис переключается на
основной репозиторий (PATCH `repo`/`branch`, ADR-040).

### 2. Шесть итераций билда до live

| Деплой | Ошибка | Причина |
|---|---|---|
| dep-dbobet2j | `Command "turbo" not found` | `pnpm turbo` = рекурсивный exec, бинарь turbo лежит в корневом `.bin` (node-linker=hoisted) |
| dep-dbobffff | `nest: not found` | заменил на `--filter=@agromoll/api run build` — но API-скрипту нужен turbo-порядок `^build` (types/validation) |
| dep-dbobgkvj | `turbo not found` (при `pnpm -w exec`) | то же, что dep-dbobet2j + установка вообще не ставила devDeps |
| dep-dbobh52j | диагностика | node_modules 745 пакетов, но `.pnpm` пуст — «частичная» установка |
| dep-dbobif7f / dep-dbobkcgu | диагностика / `rm -rf` не помог | `pnpm install` exit 0 за 2 сек без вывода — no-op |
| **dep-dboblltg** | — | **live** (18:11 UTC) |

**Корневая причина** (воспроизведена локально перед фиксом): Render
задаёт `NODE_ENV=production` **на этапе билда**, а pnpm 9 в этом режиме
молча пропускает devDependencies — «devDependencies: skipped because
NODE_ENV is set to production», exit 0, пара секунд. Ни turbo, ни nest,
ни prisma-CLI не попадают в node_modules. Дополнительно
`NPM_CONFIG_CACHE`/`NPM_CONFIG_STORE_DIR=/opt/render/.cache` ломают
кэш npx (pnpm читает NPM_CONFIG_*-переменные).

**Рабочий buildCommand** (задокументирован в `render.yaml` и ADR-040):

```bash
rm -rf node_modules && \
  env -u NPM_CONFIG_CACHE -u NPM_CONFIG_STORE_DIR -u NPM_CONFIG_LOGLEVEL \
  npx pnpm@9.15.9 install --frozen-lockfile --prod=false && \
  npx pnpm@9.15.9 -w exec turbo run build --filter=@agromoll/api
```

**startCommand** — миграции на старте (идемпотентны, подхватывают новые
миграции при автодеплоях) + запуск:

```bash
node node_modules/prisma/build/index.js migrate deploy \
  --schema apps/api/prisma/schema.prisma && node apps/api/dist/src/main.js
```

### 3. БД: миграции и сид

Миграции 17/17 и демо-сид применены на Neon заранее, из окружения агента,
по **direct**-строке (без pooler — advisory locks и DDL в transaction-режиме
PgBouncer ненадёжны): `prisma migrate deploy` + `db:seed` (идемпотентен).
Состояние проверено: 45 лотов, 27 пользователей (16 продавцов, 6
покупателей, 3 водителя, 2 арбитра), 15 фото лотов (внешние
picsum.photos), брони/долги/доставки/споры/блокировка 289-ФЗ с апелляцией.
