## 2. FCM/VAPID — где они должны жить

Проект `agromoll-web` в Vercel **не содержит ни одной** переменной
окружения. Это корректно отражает текущую архитектуру:

- `EXPO_PUBLIC_API_URL` — вшивается в бандл **на сборке** web-версии
  (ADR-022). Пока публичного API нет, сайт честно показывает экран
  «Сервер не настроен» — решение v0.6.1-0 (см. DEPLOY.md).
- `FCM_SERVICE_ACCOUNT_JSON`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`,
  `VAPID_SUBJECT` — переменные **API-сервера** (ADR-031): web-клиент
  получает публичный VAPID-ключ с API (`GET /notifications/vapid-public`),
  он не вшит в бандл. Класть их в Vercel Env web-проекта нельзя —
  они не будут использованы.
- API (NestJS + Postgres/PostGIS + Redis) пока не опубликован —
  работает только локально (`docker compose up`). Поэтому «настроить
  FCM/VAPID в проде» сейчас невозможно в принципе: нечего настраивать.
  Push-каналы работают в Noop-режиме (задумано в ADR-031), приложение
  от этого не страдает.

**Не блокирует** подэтапы B–F: всё новое (S3, переписка, фото, тайлы)
разрабатывается и тестируется локально/в CI.

## 3. Роль арбитра

Прод-БД нет (см. выше). Два пути, когда API будет опубликован:

1. **Seed** (демо-данные): `pnpm --filter @agromoll/api exec prisma db seed`
   создаёт арбитра `+79611230004` (демо-аккаунт).
2. **SQL** (назначить реальному пользователю):

```sql
-- назначить арбитра по телефону:
UPDATE users SET role = 'arbitrator' WHERE phone = '+7XXXXXXXXXX';
-- проверить (колонки camelCase — в кавычках, как создал Prisma):
SELECT id, phone, "displayName", role FROM users WHERE role = 'arbitrator';
```

Роль `arbitrator` входит в enum `UserRole` (schema.prisma), менять
schema не нужно. Через API роль арбитра себе назначить нельзя — только
напрямую в БД (исключение конфликта интересов, ADR-033).
